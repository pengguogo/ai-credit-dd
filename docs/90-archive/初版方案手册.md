# 金融壹账通 AI 马拉松 · 初版方案手册

> 目标：比赛当天 30 分钟内从零跑起一个带品牌、带数据、可解释的金融 Agent Demo。
> 对应 goal：「整理素材 → 按同类场景准备数据 → 打磨 skills」

---

## 1. 场景调研（同类赛事共性）

参照最近同类赛事（昇腾×AtomGit 金融 Agent 黑客松、业财 AI 黑客松、平安系 AI 应用赛）的共性规则：

| 评审要点 | 含义 | 对策 |
|---|---|---|
| 现场必须跑通真 Demo | 拒收 PPT / 录屏 / Mockup | ocft-starter 本地一键起服务，演示走真实交互 |
| 可解释可追溯 | 金融合规硬要求 | 所有数据集自带决策依据字段（结论依据/规则/模式） |
| 业务闭环 | 从输入到工单/赔付/拦截的完整链路 | 数据集内含状态机与流程定义 |
| 效率提升可量化 | "准确率不足 60%" 类痛点 | docs.js 自带抽取评测基准，现场可跑对比 |

五大高频赛题方向（均已配数据 + 演示面板）：
1. 智能风控 / 信贷审批
2. 反欺诈 / 异常交易拦截
3. 智能理赔 / 核赔
4. 智能客服 Agent（适老化、工单闭环）
5. 金融文档智能（研报/财报/公告解析）

- 架构：`llm.py`（OpenAI 兼容适配器，DeepSeek/GLM/Qwen 预设，全部带 fallback 降级）+ `routers/`（5 场景）+ `seed.py`（与前端 mock 逐字段一致）
- 决策模式：**规则引擎先行、LLM 增强** —— 规则算 decision（可解释），LLM 只生成意见书文案（断网不挂）
- 契约层：`contracts/` 下 `types.ts`（前端直接 import）+ `api.md`（端点表/示例/SSE 协议）+ `openapi.json`（自动导出）

## 3. 五大方向作战表（读题后 5 分钟定向）

| 命题关键词 | 用哪套 | 现场叙事主线 |
|---|---|---|
| 信贷、审批、风控、小微企业融资 | credit | 12 条申请 → 规则引擎逐条解释 → 三态分流（通过/复核/拒绝） |
| 欺诈、盗刷、异常交易、反诈 | risk | 交易流实时标注 → 3 类模式命中 → 拦截金额汇总 |
| 理赔、核赔、保险、快赔 | claims | 材料核验 → 五步流程 → 自动赔付/人工/拒赔各附结论依据 |
| 客服、坐席、适老、工单 | chatbot | 多轮对话（适老案例加分）→ 意图识别 → 工单闭环 |
| 文档、研报、财报、抽取、解析 | docs | 非结构化原文 → 结构化 KPI 表 → 评测基准算准确率 |

混合命题（如"Agent + 风控"）直接组合两套数据的导出项。

## 4. 现场工作流（Skills / 工具组合）

### 阶段 A · 读题定向（0-10 分钟）
1. 对照第 3 节作战表锁定方向，不重新发明数据
2. 用 brainstorming 思路快速明确：输入是什么 → Agent 做什么决策 → 输出给谁看

### 阶段 B · 搭建原型（10-90 分钟）
1. 起项目：`ocft-starter` → `npm run dev`
2. 复制对应场景面板到正式页面，替换 Hero 文案
3. 数据接线：`import {...} from './data'`，字段与 `*Schema` 对齐
4. UI 打磨：调 frontend-design skill（避免 AI 味通用界面，用品牌 token）

### 阶段 C · 后端扩展（10-90 分钟与 B 并行）
1. 起后端：`cd ocft-backend && .venv/bin/uvicorn app.main:app --port 8000`（Swagger `/docs` 自查）
2. 按题面只改各自场景的 `routers/xxx.py` 与 `seed.py`，**不动公共层**（llm.py/schemas.py/db.py）
3. 字段变更先改 `contracts/types.ts` + `app/schemas.py` 再改代码（契约先行）
4. 部署：web-dev MCP `deploy_to_remote`（公网 URL，评委可访问）；LLM key 走 `.env`，公网 LLM API 直连
5. 评委只信"现场跑通"，公网部署是强加分项

### 阶段 D · 验证与演示（最后 30 分钟）
- chrome-devtools MCP：截图走查 + console 零报错确认
- 演示路径彩排一遍：按"叙事主线"列的顺序点给评委看
- 答辩材料：2slides-ppt-generator 生成提纲页；可选 hyperframes 录制 30 秒产品视频

### 避坑
- 不要现场换技术栈；不要用假截图；金额展示保持 `tabular-nums` 等宽
- 可解释性话术模板：「该笔结论由规则 R002 触发，依据是负债比 0.61 > 0.55」

## 5. 人员分工与作战时间线（5 后端 + 1 前端，总时长 <24h 含夜间休息）

> 前提：公共层先行搭好（后端骨架、前端 5 面板 + 契约），比赛当天只做场景扩展。

### 角色分工

| 角色 | 认领 | 比赛当天做什么 |
|---|---|---|
| 后端 A | credit | 按题面调 `routers/credit.py` 规则阈值/新增规则，扩展 seed 数据 |
| 后端 B | risk | 调 `routers/risk.py` 检测模式，扩展交易流数据 |
| 后端 C | claims | 调 `routers/claims.py` 五步流程与决策优先级 |
| 后端 D | docs | 调 `routers/docs.py` 抽取 prompt 与评测 case（跑量化指标） |
| 后端 E | chat + 公共层 | SSE/意图规则微调；**兼任 LLM 接入与部署负责人**（.env 配 key、deploy_to_remote） |
| 前端 F | 全部面板 | 按 `contracts/api.md` 把 mock 切真实 API（`VITE_API_BASE`），逐面板联调 + UI 打磨 |

### 时间线（有效作战约 16h，夜休 6-7h 按现场规则浮动）

| 时段 | 动作 | 产出 |
|---|---|---|
| T+0~15m | 全员读题定向（§3 作战表）| 锁定主场景 + 叙事主线 |
| T+15~60m | 契约对齐：后端 E 主导 schemas 变更清单，前端 F 确认 | 变更后的契约（types.ts） |
| T+1~4h | B~F 并行：后端改各自 router+seed，前端先 mock 对齐面板 | 各场景可独立演示 |
| T+4~8h | 场景深化：规则/检测/评测指标跑分；后端 E 完成部署公网 | 公网 URL 可访问 |
| T+8~10h | 联调：前端切 `VITE_API_BASE`，逐面板过 34 项走查口径 | 前后端真实数据闭环 |
| T+10~15h | 打磨：可解释话术、量化指标、品牌一致性（§6 自检清单） | Demo 完整态 |
| T+15~16h | 彩排演示路径 + 答辩材料（2slides / hyperframes） | 路演就绪 |

### 协作铁律
- 契约先行：任何字段变更 → 先 `contracts/types.ts` + `app/schemas.py` → 广播给前端 F → 再改代码
- 后端互不踩脚：只动自己场景的 router/seed，公共层变更必须过后端 E
- 断网兜底：所有 LLM 调用带 fallback，key 失效时演示自动降级为规则文案，不挂场
