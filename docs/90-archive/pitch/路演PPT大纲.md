## P1 封面
- 标题：企业智能信贷尽调 Agent：主控 + 六角色协作，数字可复算，结论有证据
- 副标题：赛题 04 · 团队名 · 日期

## P2 痛点与目标（带过）
- 人工尽调：跨工商、财报、舆情、诉讼、担保多源取数，耗时长、口径不一致
- 纯大模型：数字会编、结论没依据、不可审计
- 目标：输入一笔贷款申请，输出五部分尽调报告、风险评级、建议额度，每个结论都能追溯到证据

## P3 一句话方案（带过）
> 规则和计算交给代码，分析和成文交给模型，复核交给人。

三个关键词：多 Agent 协作 / 确定性计算 / 证据闭环

## P4 业务架构（重点）

版式建议：从左到右泳道图。顶部是三类用户，中间是业务主流程，底部是数据与政策底座。

### 4.1 三类用户（顶部）
| 角色 | 能做什么 |
|---|---|
| 客户经理（viewer） | 查看企业基础信息，发起完整尽调，或单步执行尽调 1–5 步，继续追问 |
| 审批复核（reviewer） | 工作台审批表（待审批 / 已通过 / 已驳回），对待确认结论进行确认或驳回 |
| 管理员（admin） | 用户与角色管理、数据列表维护（按表导入、增删改查） |

### 4.2 业务主流程（中间，五段）
1. 申请受理：选择企业与贷款申请，或用自然语言提问；有歧义时先澄清
2. 数据接入：9 类企业事实（基础信息、股东、财务、舆情、诉讼、关联方、担保、风险、贷款申请），CSV 导入，现场新样本走同一入口
3. 智能尽调（六角色）
   - 并行取证：工商核验 / 财报解析 / 舆情扫描
   - 关联研判：反欺诈（财务背离、关联担保、失信限高等规则）
   - 风险与授信：评级授信（点数制评分卡 → 风险等级 → 额度测算）
   - 报告成文：五部分尽调报告 + 事实校验
4. 人工复核：角色降级、评分卡要求复核、额度无法测算这三类情况进入「待确认」，由审批人确认或驳回，并留审计
5. 结果输出：尽调报告预览（8 页版式，可打印为 PDF）、追问问答、官方六列结果批量导出

### 4.3 业务底座（底部）
- 政策配置：评分卡 `scorecard.yaml`、额度模型 `credit_model.yaml`、反欺诈规则、指标定义、舆情评分；改配置不改代码
- 运行时 Skill：六个角色各一份业务 Skill（工商核验、财报分析、舆情扫描、反欺诈、额度测算、尽调报告），按角色下发，执行时记录版本
- 输出定位：测算建议，非授信审批

讲述要点：业务流程对应真实信贷尽调的「受理 → 调查 → 审查 → 审批」，Agent 替代的是调查和起草环节，审批权保留在人手里。

## P5 技术架构（重点）

版式建议：左侧画自上而下分层图，右侧放 4 个设计亮点卡片。

### 5.1 分层（左侧）
```
前端      React 19 + TypeScript + Vite + Tailwind + shadcn/ui + ECharts
          工作台 / 数据列表 / 多 Agent 协作视图 / 证据抽屉 / 报告预览 / 系统管理
              │ REST + SSE 实时事件
接口层    FastAPI routers：agent / auth / admin（只做校验与响应）
              │
服务层    run_service（事务、终态落库）· dd_step 单步尽调 · csv_import · memory · auth
              │
Agent 层  主控 engine（有界工具循环，LangGraph 调度）
          └ run_dd_agents → 六角色子图 dd_graph
              工商 ┐
              财报 ├→ 反欺诈 → 评级授信 → 报告 → 事实校验 dd_verify
              舆情 ┘
              │
工具层    注册表 @register_tool：dd_calc 纯函数计算 · 尽调取数 · sql_query（语法树白名单）
              │
横切      合规：输入/输出审查、PII 掩码、代号化脱敏 │ 可观测：Request-ID、run_events、审计、调用审计
              │
持久层    SQLAlchemy + 增量迁移；MySQL（SQLite 本地兜底）
模型      仅经 llm.py 调用 deepseek-v4.1-flash
```

### 5.2 四个设计亮点（右侧卡片）
1. 先算后写：每个角色先由 `dd_calc` 纯函数算出全部数字，再调一次模型写结构化解读；模型不能改数字
2. 事实校验闸门：报告里的每个金额、等级、期间都和计算结果比对，不通过就带问题清单重写一次，仍不通过则如实返回失败，不出模板答案
3. 配置驱动：角色依赖、Token 上限、超时、Prompt 都在 `agents.yaml`，政策在 yaml，新样本优先改配置
4. 全链路代号化：企业名、人名、信用代码、证件号、地址送模型前转为代号，工具在本地还原后查库；主控与六角色共享同一次 run 内的映射

讲述要点：LangGraph 只负责调度，模型入口、工具注册表、终态判定、证据事务全部自研；不接任何低代码平台。

## P6 可信与合规（带过）
- 证据闭环：结论 → evidence 行 → 当次快照，前端可展开查看
- 终态如实：成功 / 待确认 / 证据不足 / 澄清 / 拦截 / 失败
- 答案隔离：运行时不读标准答案和外部汇总评级（含 `sql_query` 列级黑名单），答案只在 `eval/` 离线比对
- 输入输出合规：五类敏感词、注入与越狱拦截、PII 掩码

## P7 效果数据（带过，路演前需用冻结版本复跑核数）
- 官方公开集 10 笔申请，真实模型：风险评级 10/10、建议额度 10/10，终态 6 笔成功、4 笔待确认
- 平均耗时约 50 秒 / 笔
- 后端测试 425 项通过，红线扫描 0 ERROR
- 需如实披露：评分卡阈值和额度取整档位用公开集校准过，非公开集在档位边界附近可能有偏差
