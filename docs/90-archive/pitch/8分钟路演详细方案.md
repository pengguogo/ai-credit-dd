# 8 分钟路演详细方案：企业智能信贷尽调 Agent

> 适用：赛题 04 现场路演，也可作为 8～10 分钟演示视频的 8 分钟版本。  
> 推荐形式：**6 页 PPT + 1 次现场真实运行 + 1 次自然语言追问 + 1 条历史高风险记录**。  
> 核心原则：业务价值优先，不堆技术名词；现场运行证明能力；所有数字说明证据范围，不把内部模拟评分称为官方成绩。

---

## 一、评委最终应记住的三句话

1. **这不是把多张 CSV 一次性丢给大模型，而是一套完整的多 Agent 信贷尽调系统。**
2. **规则和数字由代码实时计算，模型负责分析和成文，每个关键结论可以回到证据。**
3. **系统不替审批人拍板：高风险进入人工确认，失败、证据不足和合规拦截都会如实呈现。**

一句话定位：

> **让 AI 做调查员，把审批权留给人：规则负责算准，Agent 负责协作，证据负责说清，人负责最终决策。**

路演主线：

> 一笔贷款申请如何经过多源取证、六角色协作、规则计算和事实校验，形成一份可解释、可审计、可人工接管的尽调建议。

不建议把主线做成技术栈介绍、七项功能逐条念稿、团队开发历程或多个相似页面轮播。8 分钟里最有说服力的是一条真实运行生命线。

## 三、PPT 只做 6 页

## P1　痛点与目标（0:00–0:35）

### 页面内容

**标题：企业智能信贷尽调 Agent**  
副标题：主控 + 六角色协作｜数字可复算｜结论有证据

三行正文：

- 传统尽调：多源取数、人工计算、手工写报告；题目背景中的典型周期为 3～5 天；
- 纯大模型：数字易漂移、依据难追溯、过程难审计；
- 我们：把调查和报告起草标准化，最终审批权仍留给人。

### 讲稿

> 各位评委好，我们展示的是企业智能信贷尽调 Agent。传统尽调需要客户经理在财报、工商、舆情、诉讼和担保等信息之间来回核对，题目背景中的典型周期是 3 到 5 天，而且结果高度依赖个人经验。如果只是把多张表一次性发给大模型，数字可能漂移，结论也很难追溯。我们要解决的不是“让模型写一篇报告”，而是把一笔贷款申请变成一条可计算、可解释、可审计、可人工接管的尽调流程。

提醒：“3～5 天”是赛题背景，不是本系统做过的生产效率对照实验。

## P2　一句话方案（0:35–1:05）

### 页面内容

**规则和计算交给代码，分析和成文交给模型，最终复核交给人**

三个卡片：

1. **确定性计算**：财务指标、反欺诈规则、风险评级、额度步骤；
2. **多 Agent 协作**：工商/财务/舆情并行，反欺诈、评级授信、报告依次汇合；
3. **可信治理**：证据快照、事实校验、六种终态、人工确认、审计留痕。

页脚：HTTP、SSE 和批量评测共用同一运行入口，没有演示专用答案路径。

### 讲稿

> 我们的方案可以概括成一句话：规则和计算交给代码，分析和成文交给模型，最终复核交给人。财务指标、反欺诈规则、评级和额度由工具从业务事实实时计算；六个角色 Agent 按依赖协作；每次运行保存证据、轨迹和审计记录。前端交互、实时事件和批量评测走同一个执行入口，不为演示另做捷径。下面不继续讲概念，我们现场提交一笔新的尽调任务，让系统边跑，我边解释它在做什么。

## 四、现场主演示

## 1. 发起真实尽调（1:05–1:25）

推荐选 **LA001 / E001**，输入：

> 企业 E001：请基于贷款申请 LA001 完成企业尽调，给出风险评级、建议授信额度、主要风险、风控条件及对应依据。

选择原因：历史真实运行可稳定展示成功终态、评级、数值额度、财务分析和证据；高风险样例更适合后面单独演示人工确认。

操作：

1. 确认当前企业 E001、申请 LA001；
2. 点击发起尽调；
3. 指出新生成的 `runId` 和“运行中”；
4. 展开 SSE 实时轨迹；
5. 不等待结果，直接讲 P3。

讲稿：

> 这里选择企业 E001 和申请 LA001。我现在现场发起任务，请注意这是刚生成的新 runId。输入先通过合规检查，随后进入和批量评测完全相同的运行服务。右侧事件会实时显示每个角色和工具的执行状态。

必须让评委看到新 runId，不能打开早已完成的页面后称为现场运行。

## P3　业务架构（1:25–2:35）

### 推荐图

```text
贷款申请 / 自然语言问题
          │
          ▼
数据接入与口径统一
          │
          ▼
工商核验 ─┐
财报解析 ─┼─ 并行取证
舆情扫描 ─┘
          │
          ▼
反欺诈 → 风险评级与额度 → 五部分报告 → 事实校验
          │
          ├─ 成功：报告 / 问答 / 批量导出
          └─ 不确定：人工确认 / 补资料 / 如实失败
```

### 七项能力如何自然带出

| 官方能力 | 演示表达 |
|---|---|
| 财报解析 | 三年科目和盈利、偿债、营运指标由工具计算 |
| 工商核验 | 基础信息、经营异常、关联企业、担保核查 |
| 舆情扫描 | 舆情、行政处罚、诉讼事件和风险标签 |
| 反欺诈 | 现金流背离、存货异常、关联担保等规则线索 |
| 额度测算 | 财务承载、风险折减、存量敞口、建议区间 |
| 报告生成 | 企业概况、财务、风险、额度、风控条件 |
| 自然语言问询 | 同一会话追问并给出依据 |

### 讲稿

> 这条链路对应真实信贷流程中的受理、调查、审查和复核。首先，工商、财务和舆情三个角色并行取证；反欺诈角色消费三路上游事实，判断现金流背离、存货异常和关联担保等线索；评级授信角色再基于确定性评分和额度步骤给出建议；最后由报告角色形成五部分尽调报告，并通过事实校验闸门核对金额、科目、期间和风险等级。六角色不是六个静态名称，而是有真实依赖的协作链。Agent 替代的是调查和起草，不替代授信审批。

可补一句业务边界：数据缺少关联交易金额时，只提示补充核查，不声称已经算出真实交易占比。

## P4　技术架构：为什么可信（2:35–3:30）

### 页面图

```text
React 工作台
  │ POST /api/agent/runs + SSE
  ▼
FastAPI → run_service（事务与终态）
  ├─ 输入合规：命中即 blocked，不调用模型
  ▼
LangGraph 调度主控与六角色
  ├─ deepseek-v4.1-flash，仅经 app/llm.py
  ▼
工具注册表 → 只读取数 / 规则计算 / 参数白名单
  ▼
evidence 快照 → 输出合规 → 轨迹、消息、审计落库
  ▼
高风险业务确认（幂等 + 版本校验 + 留痕）
```

右侧四点：

- **先算后写**：工具算数字，模型负责解释；
- **证据绑定**：来源、记录、科目、期间、快照可追溯；
- **诚实终态**：成功、待确认、待澄清、证据不足、拦截、失败；
- **配置驱动**：角色依赖、Skill 和政策规则可配置。

### 讲稿

> 技术上，我们没有让大模型直接对整包 CSV 自由作答。前端通过 REST 发起任务，通过 SSE 看实时事件；服务层统一管理事务和终态；LangGraph 只负责调度主控与角色依赖；所有模型调用只能经过唯一入口，并锁定比赛指定模型。业务数据通过工具注册表读取，参数有结构校验，结果形成 evidence 快照。答案、轨迹、证据、合规记录和审计一起保存。模型即使超时或表达降级，系统也会保留计算事实、提示人工复核，而不是补一个看起来完整的假结论。

8 分钟内不要讲组件库、ORM、迁移、所有 YAML 字段、完整 Prompt 或 token 配置。只讲清统一入口、唯一模型入口、工具计算、证据落库和诚实终态。

## 2. 展示本次结果（3:30–4:35）

只展示三个区域：

### A. 评级与额度

> 系统给出了风险评级和建议额度。这个额度不是模型拍脑袋生成，而是由工具根据财务承载、风险折减、存量敞口等步骤计算，模型只负责解释依据。它是尽调建议，不是最终审批。

### B. 报告两个重点

只滚到近三年财务和主要风险/风控条件，不要从头念完整报告。

> 报告按企业概况、财务分析、风险提示、额度建议和风控条件五部分组织。这里重点看财务事实和风险条件，金额、期间和风险描述都可以继续核查。

### C. 展开一张证据卡

优先选经营现金流、营业收入、涉诉或额度步骤，展示来源、记录 ID、期间、科目、金额和快照。

> 我点开这一条结论，可以看到数据来源、记录标识、期间、科目和本次快照。即使未来数据变化，也能复盘当时为什么得到这个结论。

如页面稳定，再打开：`/report-preview.html?runId=<本次运行编号>`。

> 这个报告预览读取刚才 runId 已落库的结果，不会重新调用模型生成另一份答案。

## 3. 自然语言追问（4:35–5:20）

推荐问题：

> 该企业近三年的成长性如何？请分别列出营业收入、净利润和经营现金流依据，并说明是否需要人工复核。

讲稿：

> 尽调不是一次性报告。客户经理可以在同一会话继续追问。这里要求系统把营业收入、净利润和经营现金流分别列出，并标明是否需要复核。系统要先识别意图，再调用合适工具获取科目、期间和金额，而不是只从上一段文字继续编写。

若 40 秒内未返回：

> 现场模型调用仍在执行，轨迹已经显示它正在获取财务依据。为了控制时间，我先进入下一部分；完成后结果会保留在同一个运行记录中。

不要刷新、重复提交、临时换题，或用预制答案冒充本次结果。

## 4. 高风险人工确认（5:20–5:55）

提前准备一条**历史真实运行**的 LA003 或 LA006 `needs_confirmation` 记录。切换时必须先说：

> 接下来这条是历史真实运行记录，用来展示高风险治理流程，不是刚才任务的一部分。

展示状态、待确认原因、reviewer/admin 入口和审计时间线。

> 当系统识别到高风险拒贷方向、角色降级或关键不确定项时，不会把模型建议直接当作审批结果，而是进入待确认。只有具备权限的复核人员可以确认或驳回，并记录操作者、时间、答案版本和意见。我们的目标不是让 AI 替人承担审批责任，而是让调查过程更快、更一致、更可追溯。

注意：历史 LA003/LA006 正文曾存在涉诉覆盖或复核措辞问题。这一段只证明治理闭环，不要把旧正文作为“完全正确”样板；`needs_confirmation` 也不等于已审批。

## 五、效果、泛化与收口

## P5　实测数据（5:55–6:45）

### 推荐四个大数字

| 指标 | 数字 | 必须说明的口径 |
|---|---:|---|
| 风险评级 | **10/10** | 已提交版历史真实模型公开批次，评级字段严格一致 |
| 数值额度区间 | **8/8** | 只统计官方给出数值区间参考的 8 笔；另 2 笔为拒贷/极小额度语义参考 |
| 申请证据覆盖 | **10/10** | 每笔申请有 evidence，不代表每个自然语言断言已签核 |
| 平均申请耗时 | **73.2 秒** | 历史批次；P95 97.588 秒，不承诺固定 SLA |

小字可补：历史 10 笔申请为 8 成功、2 待确认；10 道问询为 9 成功、1 待确认且均有证据。当前工作区 463 项后端测试通过、前端 lint/build 退出 0、红线扫描 0 ERROR，但这是工程回归，不是业务准确率。

### 讲稿

> 再看经过边界说明后的实测数据。在已提交版历史真实模型批次中，公开 10 笔申请的风险评级字段 10 比 10 一致；官方给出数值区间参考的 8 笔，额度区间 8 比 8 一致，另外两笔是拒贷或极小额度的语义参考，不把它们硬算成数值命中。10 笔申请都有 evidence 记录，平均耗时 73.2 秒。我们明确区分字段匹配、证据存在和正文正确性：复杂趋势、因果和逐要点覆盖仍需人工核验，不能用字段一致代替“全文 100% 正确”。自动化测试也只证明工程回归，不等于业务准确率。

## P6　泛化、合规、边界与总结（6:45–8:00）

### 页面左侧：未见企业如何处理

- 新企业走同一数据导入、计算、证据、报告和导出管道；
- 角色依赖、Skill、评分卡、额度和反欺诈规则配置化；
- 批量入口与前端共用 `run_service.create_run`；
- 非公开集没有答案时只运行和导出，不读取 `expected` 作答；
- 失败与待确认原样保留，不回填模板答案。

### 页面右侧：主动边界

- 运行时只使用 `deepseek-v4.1-flash`，只经唯一模型入口；
- 输入输出做合规检查，外送前对受约束字段脱敏；
- 图片入口当前主动返回 422，避免未经验证的图片直接外送；
- 通用批量输入支持 JSON/JSONL/CSV/XLSX，**尚不支持 PDF**；
- 非公开集需现场真实运行，当前不声称已经通过；
- 输出是尽调建议，不是授信审批决定。

### 6:45–7:25 讲稿

> 现场非公开集会是未见过的新企业，只有输入，没有答案。我们的做法不是建立题号到答案的映射，而是让新样本继续走同一条数据导入、工具计算、Agent 分析、证据保存、报告和导出管道。角色依赖、Skill 和业务规则都通过配置管理，新场景优先改配置而不是改执行引擎。运行时看不到 expected；如果材料不足、模型失败或高风险需要复核，系统会原样保留对应终态，不回填模板答案。

> 我们也明确当前边界：通用批量入口支持 JSON、JSONL、CSV 和 XLSX，尚不支持 PDF；图片入口在未完成可验证脱敏前主动拒绝；非公开集必须等现场输入后真实运行，我们不会提前宣称已经通过。

### 7:25–8:00 收口稿

> 最后总结，我们不是让一个大模型读完 CSV 后给出一个看似专业的答案，而是把企业信贷尽调拆成可执行、可核验的协作流程：代码把数字算清楚，六个角色把信息组织起来，证据把结论说明白，人工确认守住最终决策。它的价值不是替客户经理和审批人拍板，而是把原本分散、依赖经验的调查和报告起草，变成一条可实时计算、可解释、可审计、也能在不确定时诚实停下来的标准化链路。我们让 AI 做调查员，把审批权留给人。谢谢各位评委。

## 六、完整连贯口播提纲

为方便背稿，可将全场压缩为以下 12 个记忆点：

1. 人工尽调慢、口径依赖经验；纯模型数字与依据不稳定。
2. 我们不是写报告工具，而是完整尽调链路。
3. 规则算数、模型分析、人来复核。
4. 现场提交 E001/LA001，指出新 runId。
5. 工商、财务、舆情并行取证。
6. 反欺诈 → 评级额度 → 报告 → 事实校验。
7. 唯一模型入口、统一运行入口、工具参数校验。
8. 展示评级额度、报告重点和一张证据卡。
9. 同一会话追问成长性和三项财务依据。
10. 历史高风险记录进入人工确认并留痕。
11. 报四个带口径的数字：10/10、8/8、10/10、73.2 秒。
12. 未见样本走同一管道；主动说 PDF、图片、非公开集等边界；收口“AI 做调查员，审批权留给人”。

- [ ] 当前对象确实为 E001/LA001；
- [ ] 输入框、错误提示已清理；

2. 慢速轮：完整运行超过 2 分钟，追问未返回；

## 八、现场故障预案

### A. 模型慢，但轨迹推进

> 当前模型调用仍在执行，右侧轨迹显示任务没有停止。为了不占用路演时间，我先用一条明确标注的历史真实运行记录展示结果结构；本次 run 完成后会正常落库，我们不使用预制结果替换它。

### B. 本次任务失败

> 这次运行进入了结构化失败状态。系统没有回填模板结论，这正是诚实终态的设计。下面我用历史真实记录展示已完成报告，但不把它称为本次结果。

### C. 数据库或 Redis 不可用

打开就绪检查，说明具体依赖不可用。不要反复重启，不要声称系统此刻可运行。

### D. 页面或投影异常

继续 PPT；可展示本地保存的真实报告截图，但必须说“历史真实运行截图”。不要现场打开开发者工具维修。

### E. 评委要求换企业

先确认输入格式和企业/申请标识。若数据未导入：

> 当前输入还没有进入业务数据层，系统不会凭空生成结论。我们先按数据模板导入校验，再发起同一执行链路。

## 九、高概率问答

### 1. 为什么需要多 Agent？

> 不是为了角色数量，而是隔离职责和建立依赖。工商、财务、舆情并行取证，反欺诈消费三路事实，评级授信消费风险结果，报告最后汇总。每个角色有输入输出契约、Skill 版本和失败状态，便于定位错误与复用能力。

### 2. 如何防止模型编数字？

> 关键数字先由工具从业务数据计算，模型负责结构化解读；金额、科目、期间和等级再经过事实校验，关键结论关联 evidence。复杂自然语言因果仍可能需人工核验，所以不宣称消除了所有幻觉。

### 3. 是否根据公开集写死答案？

> 没有题号到答案映射。运行时不读取 expected，公开答案只在 eval 离线评分侧使用，执行前还做泄漏检查。公开数据可用于通用参数校准，但泛化能力必须由现场未见企业证明。

### 4. 风险评级和额度是谁决定？

> 由确定性评分卡和额度模型根据输入事实计算，模型只解释。计算和折减步骤可追溯，结果是尽调建议，最终审批由业务人员完成。

### 5. 高风险拒贷如何处理？

> 进入 `needs_confirmation`，不会自动生效。复核人员确认或驳回时记录身份、时间、答案版本和意见。

### 6. 非公开数据怎么适配？

> 按数据关系导入校验后走同一入口；角色依赖、Skill 和政策规则配置化。没有 expected 时只运行和导出，不自行宣称正确率。

### 7. 能完全离线吗？

> 依赖和前端资源可离线安装；实际答题仍需访问指定模型 API 和当前配置的 MySQL、Redis。因此准确说法是“离线安装”，不是“全系统断网答题”。

### 8. 支持 PDF 吗？

> 当前支持 JSON、JSONL、CSV、XLSX，尚未完成 PDF 输入链路验证，所以不宣称支持。

### 9. 为什么平均 73 秒？

> 完整任务包含三路取证、反欺诈、评级授信、报告和事实校验，并调用指定模型生成结构化解读。73.2 秒是历史平均值，不是 SLA；后续可优化上下文和无效调用，但不牺牲证据与校验。

### 10. 最大不足是什么？

> 复杂趋势、因果和报告逐要点正确性仍需全量业务签核，非公开样本需现场验证，输入端尚未完成 PDF 支持。我们用事实校验、证据和人工确认管理这些边界，而不是用模板结论掩盖。

## 十一、最简 6 页 PPT 文案

1. **企业智能信贷尽调 Agent**：主控 + 六角色协作｜数字可复算｜结论有证据。
2. **规则和计算交给代码，分析和成文交给模型，最终复核交给人。**
3. **一笔申请的完整生命线**：受理 → 数据 → 三路取证 → 反欺诈 → 评级额度 → 报告 → 校验 → 人工复核。
4. **模型负责理解与表达，系统负责边界与责任**：统一入口｜唯一模型入口｜工具校验｜证据｜六种终态｜审计。
5. **历史真实模型批次**：评级 10/10｜数值额度 8/8｜申请证据 10/10｜平均 73.2 秒。页脚注明口径和“非官方评分”。
6. **让 AI 做调查员，把审批权留给人**：可计算｜可解释｜可审计｜可人工接管｜未见样本走同一管道。

## 十二、最终取舍

8 分钟内容优先级：

1. 现场新 run 的完整生命线；
2. 工具计算 + 证据 + 事实校验；
3. 六角色真实依赖；
4. 评级、额度、报告、追问；
5. 高风险确认和诚实终态；
6. 带口径的历史数据；
7. 未见样本走同一管道；
8. 主动披露边界。

应压缩：技术栈、团队介绍、开发过程、全部测试数字、多个相似案例、不能现场证明的效率或收益数字。

判断标准：一句话若不能帮助评委理解“业务价值、真实链路、可信机制、实际效果、泛化能力”中的至少一项，就不应占用这 8 分钟。
