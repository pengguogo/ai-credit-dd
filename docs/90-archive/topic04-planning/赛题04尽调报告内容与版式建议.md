# 赛题04尽调报告内容与版式建议

日期：2026-10-24

状态：讨论稿。配套HTML已按当前数据库中的E002 / LA002生成静态预览，使用实际库内模拟资料、现有工具计算及一次真实模型解读；不是完整Agent链路生成并落库的正式报告。

配套文件：[固定案例HTML预览](赛题04尽调报告固定案例预览.html)。

## 一、结论

建议把PDF从“聊天答案的文字打印件”升级为“结构化业务结果的报告”。保留赛题要求的企业概况、财务分析、风险提示、额度建议、风控条件五部分，增加前置摘要和附录，在主体中穿插财务趋势、股权关系、事件时间线、额度计算与待核实清单。

目标是让客户经理可以快速阅读结论、检查依据、发现缺口，再下钻明细。内容多少应取决于实际数据和结论，不能为了增加页数添加无依据的文字、图表或评分。

## 二、现有PDF单调的工程原因

依据当前工程文件检查：

- `ocft-starter/src/lib/answer-export.ts` 的 `answerBlocks()` 主要解析标题、正文、列表与表格，没有财务图表、事件时间线、关系图等报告组件。
- PDF通过Canvas绘制文字及表格，再将JPEG页面装入PDF。现有路径难以直接保留HTML中的图表、布局和可选择正文。
- `ocft-backend/scenarios/dd04/prompts/report.md` 要求完整报告控制在900字以内；`skills/dd-report.md` 规定了紧凑的Markdown骨架。文字精简并不意味着工具没有更丰富的财务、事件和计算数据。
- 工具结构化数据、角色分析、最终答案和导出之间，尚需明确完整报告的专用数据契约。不能假设工具字段已经全部暴露给前端。

因此，仅加长提示词不能解决全部问题。需要同时设计报告数据、成文预算、图表渲染、证据关联及导出方式。

## 三、赛题要求与设计边界

依据[题目说明](../../00-rules/赛题/赛题04_企业智能信贷尽调/题目说明.md)及[提交材料说明](../../00-rules/赛题/赛题04_企业智能信贷尽调/提交材料说明.md)：

- 覆盖近三年财务、工商、舆情、反欺诈、额度及报告全链路。
- 报告必须包含五部分：企业概况、财务分析、风险提示、额度建议、风控条件。
- 结论与风险评级、指标、测算依据一致；可解释到科目、期间、规则和记录。
- 至少提供一份由系统生成的完整结构化报告成品，导出敏感字段脱敏。
- 至少三张真实报告界面截图。固定设计稿不能替代系统真实截图。
- 不编造法规或阈值，不把不确定线索写成已经查实的欺诈。

本次没有读取公开测试答案、问题参考要点或外部汇总评级来填充案例。HTML从当前数据库白名单业务字段提取E002 / LA002，名称通过现有Masker代号化；不接入运行时、不进入种子数据，不作为正式答案或提交样例。

## 五、建议包含的内容

### 5.1 前置摘要

- 企业、申请、报告编号及版本。
- 数据截止日、财务年度、生成时间、计量单位。
- 风险等级、建议额度、期限和复核状态。
- 主要支持因素、主要关注事项。
- 核心结论及数据限制。

不建议采用只有大标题的独立封面；第一页就应该可以帮助读者理解判断。

### 5.2 企业概况

- 主体、经营状态、行业、资本和实缴情况。
- 股权、实际控制、关联企业和担保关系。
- 本次申请金额、用途、期限、担保方式。
- 工商异常的当前和历史状态。
- 核验来源、差异和补充资料。

适合股权关系图、基础信息对照表。图中每条边都要有资料依据；不完整关系图不能证明不存在担保圈。

### 5.3 财务分析

- 三年营收、利润、资产、负债、权益、经营现金流。
- 净利率、资产负债率、现金流利润比及相应公式。
- 应收、存货等营运资金占用。
- 同比、趋势、勾稽、审计意见与限制。
- 第一还款来源及所缺分析输入。

适合收入柱状图、利润与现金流对照、资产负债结构，以及精确数据表。金额与比率不混用无说明的坐标轴；年份缺失不补零。

缺少成本不计算毛利率、存货周转天数；缺少还本付息计划不计算精确DSCR；没有来源可靠的行业样本，不添加“行业均值”。

### 5.4 风险提示

- 风险评级、评分因素、政策版本、否决项。
- 舆情及诉讼事件时间线，含编号、日期、来源、状态、身份和金额。
- 反欺诈命中、原始事实与核实建议。
- 关联和担保风险。
- 数据缺失、来源冲突及人工复核事项。

可用事件卡片、风险清单和有明确因素依据的评分贡献图。不要用未经校准的“欺诈概率”、随意雷达分数或视觉化风险热度替代证据。

### 5.5 额度建议

- 申请额、建议额、期限、利率方向和担保条件。
- 计算年度、收入与权益约束、风险调整、申请额封顶及取整步骤。
- 存量和担保敞口处理口径。
- 第一还款来源、第二还款支持及尚未验证的前提。
- 有明确假设和重算能力时，可增加敏感性分析。

优先展示可逐步复算的计算阶梯。利率方向不等于具体合同利率；担保申请不等于担保能力已经验证；敏感性演示不能冒充未来预测或完整压力测试。

### 5.6 风控条件

- 放款前资料和核实事项。
- 触发原因、来源证据、验收标准。
- 贷后监测主题、频率及处理建议。
- 人工复核意见、人员、时间和版本。

管理建议、批准条件、已签合同义务、法规要求需要区别，不把建议自动写成强制条款。

### 5.7 附录

- 财务指标公式与单位。
- 证据索引及来源主键。
- 输入、政策、提示词和报告版本。
- 真实执行情况及失败限制。
- 编制方法和使用边界。

模型原始思维链不属于报告交付内容；应展示可验证的业务依据、计算过程和执行事实。

## 六、本次固定案例的版式安排

HTML设计为8个A4版面，屏幕端可按目录跳转，并提供浏览器打印入口：

1. 决策摘要：结论、关键金额、支持因素和主要限制。
2. 企业概况：基础信息、申请需求、股权关系与核验清单。
3. 财务分析：收入趋势、三年财务表和盈利解释。
4. 财务分析续：利润现金流对照、营运资金与还款来源。
5. 风险提示：事件时间折线图、敞口和核查线索。横轴按库内事件日期排列，纵轴为现有工具给出的单条事件风险贡献分，正值加风险、负值减风险；不是企业整体历史风险曲线，连线不代表连续观测或插值。案件日期为立案日，不冒充结案日期；图下保留事件明细，节点支持定位。
6. 额度建议：当前工具计算步骤、评分维度与权重，不增加压力情景。
7. 风控条件：工具条件、模型建议与真实反欺诈规则结果，不虚构待办或审批记录。
8. 附录：业务表来源定位、数据提取时间、模型生成记录、快照和模型输入摘要，以及未采集的信息范围。

### 6.1 数据库版案例（替换初版虚构案例）

- 企业E002、申请LA002；申请日期2024-03-20，财务期间2021—2023。
- 数据库只读取现有业务表，不写入事实、评测或审批数据；提取时间以HTML显示为准。
- 使用现有 `dd_roles.compute()` 调用计算纯函数：评分82.29、低风险，建议额度1200—1500万元、24个月、利率方向下浮。政策为 `incremental-v1`；这些值不来自公开答案或外部汇总评级。
- 图表全部使用库内科目或现有工具计算结果，不保留独立编造的企业、事件、假设评分和敏感性预测。
- 名称由现有 `dd_snapshot.build_masker()` 代号化；身份号码和地址不展示；不外送原始敏感资料。
- 通过 `app/llm.py` 调用锁定模型 `deepseek-v4.1-flash`，基于脱敏计算摘要实际生成一次结构化解读。页面分别标注数据库事实、工具计算、模型解读，不把本次单次解读称为六角色完整执行。
- 模型只做解释与核实建议，不生成评级、额度、行业基准、假设未来数据或审批状态；模型内容已逐项对照输入核读，正式发布仍需完整运行时事实与合规校验。
- 数据库未采集的账龄、流水、抵押估值、还本付息计划等明确标记限制；不声称企业拒绝提供。
- 股权、担保及诉讼的时点资料不完整，页面不宣称已经验证2024年申请当日全部资料可得，也不视为2026年实时情况。

S01—S05是本文件的来源索引，不是数据库evidence行；未生成正式runId或写入证据表。页面显示的SHA256是本次脱敏快照及模型输入的实际摘要，不冒充已落库的证据哈希。正式报告仍应通过完整业务链路记录证据、审计与报告版本。

HTML内置样式和SVG，不依赖CDN、外部字体或图片。八个版面是设计安排，实际打印分页需在目标浏览器、A4及100%缩放下确认；浏览器自动页眉页脚建议关闭。当前不宣称已完成目标浏览器和导出PDF的视觉验收。

## 七、后续接入的实现方向

### 7.1 同一事实源，分别生成摘要与详版

摘要保留短答案体验；详版由已验证的结构化结果、角色分析和证据构建。不是前端拿企业编号套固定结论，也不为每张图单独请求模型。

### 7.2 先补报告契约

明确报告标识、申请、财务年度、章节、指标、事件、关系、计算步骤、证据关联、缺失状态及版本字段。前端图表只呈现后端已验证数据。

### 7.3 采用专用HTML报告渲染

使用可复用报告组件及打印样式，将图表和正文一起渲染。浏览器打印可以作为首期入口；是否服务端自动生成PDF需另行明确浏览器依赖、离线打包、字体和部署平台。

不能假设把本HTML交给现有Markdown→Canvas→JPEG导出就能保留图表。需要替换或扩展导出路径；全文可选中、检索和可访问性也应作为选型目标。

### 7.4 报告生成与验证

模型负责解释，工具负责数字；输出前检查数字、期间、评级、金额和证据。资料不齐、角色失败、校验失败要显示真实限制，不能用固定案例填补。

### 7.5 后续验收建议

- 五部分完整，摘要与详情、页面与PDF口径一致。
- 图形值和表格值一致，单位及计算公式明确。
- 结论可以定位到真实证据。
- 缺失年度、负数、长文本、多事件、表格跨页不截断。
- 真实企业与人员资料按规则脱敏。
- PDF分页、中文字体、可读性及离线资源在目标平台检查。
- 正式样例通过真实业务链路生成，设计稿不作为比赛结果。
