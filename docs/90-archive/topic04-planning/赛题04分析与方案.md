# 赛题 04 企业智能信贷尽调 · 分析与方案

> 状态：草稿，待黎锦涛拍板（2026-10-24）。原文见 [题目说明](../../00-rules/赛题/赛题04_企业智能信贷尽调/题目说明.md) 与 [提交材料说明](../../00-rules/赛题/赛题04_企业智能信贷尽调/提交材料说明.md)。分工见 [模块分工表](../../10-strategy/模块分工表.md)。
> 本文不抄录任何标准结果取值（红线 R4/R5）；只引用列名与题目要求。

## 一、题目要什么

**一句话**：输入一笔贷款申请（或企业编号、或客户经理的一句话问题），系统自动跑完「财报解析 → 工商核验 → 舆情扫描 → 反欺诈检测 → 额度测算 → 尽调报告」，给出风险评级、建议额度和结构化报告，并支持自然语言追问。

| 项 | 要求 | 来源 |
|----|------|------|
| 七项必选功能 | 财报解析、工商核验、舆情扫描、反欺诈检测、额度测算、尽调报告生成、自然语言问询，全部可达 | 题目说明 §三 |
| 架构 | 题目明确写"多 Agent 协作"；技术方案第 1 章要"多 Agent 架构图：角色划分、协作协议、编排方式"；README 要写"多 Agent 角色划分与编排配置路径" | 题目说明 §一、提交说明 2.2 / 2.3 |
| 可配置 | 反欺诈规则、财务指标口径、额度测算模型须有**配置文件路径**，非硬编码；非公开集"改配置优于改代码" | 提交说明 2.2、题目说明 6.2 |
| 核心交付 | `系统输出/…公开测评集结果.csv` 与 `…非公开测评集结果.csv`，列名与 `公开测试集答案.csv` 对齐：`application_id, enterprise_id, risk_level, suggested_credit_amount, due_diligence_conclusion, scoring_points` | 提交说明 2.5 |
| 截图 | 至少 3 张：完整尽调报告、财务分析明细（近三年科目与指标）、风险提示与反欺诈；建议第 4 张自然语言问询 | 提交说明 2.4 |
| 追加材料 | 至少 1 份系统生成的尽调报告成品（企业概况、财务分析、风险提示、额度建议、风控条件五部分，脱敏） | 提交说明 2.9 |
| 演示 | 8~10 分钟，当场跑出结果，建议含一次自然语言追问 | 提交说明 2.6 |
| 时效 | 内部耗时目标：单笔全链路 ≤ 30 秒。九大赛题介绍 PPT 与题目说明都没有这条时限；PPT 第 9 页只写传统尽调耗时 3–5 天。30 秒来自已删除的赛题一览旧截图，不作为官方 SLA | PPT 第 9 页 |
| 评审重点 | 风险评级、建议额度、结论与要点覆盖；**财报口径一致性**、**结论与数据事实一致**（评委随机抽条核对）；**额度测算依据可解释**（用了哪些指标、规则、假设）；规则与大模型的融合方式 | 题目说明 6.1 / 6.3 |

**不要求**：会话记录 jsonl、PDF 解析、OCR、图数据库。

|----|------|--------|-----------|

## 三、关键风险与需要拍板的事

1. **`enterprise_risk.risk_level_summary` 和标准答案的风险评级 10 笔全部相同。** 它是官方给的输入数据，读它不违反红线，但如果直接照抄当作结论：评委抽查"结论与数据事实一致性"时讲不出依据，非公开集里这一列也可能缺失或被扰动。**建议**：评级由我们的评分卡从事实算出；`risk_level_summary` 作为"外部汇总评级"展示并做一致性校验，不一致时标注"需人工复核"，不参与计算。（待黎锦涛定）
2. **"多 Agent" 与 ADR-0005（单主 Agent）冲突。** 建议写 ADR-0008：在本赛题采用"主控 + 6 个专职角色"的多 Agent 编排（见第四节），每个角色有自己的提示词与工具白名单，经 LangGraph 状态图协作；模型调用仍只经 `llm.py`、工具只经注册表，不违反 R1 / ADR-0002。
3. **`question_public.csv` 自带 `reference_answer` 列。** 批量测评只读 `question` 与 `enterprise_id`；`reference_answer` 只交评分器（需在 `eval/dataset.py` 的读取里显式排除，并加测试）。
4. **企业全名、法人姓名、统一社会信用代码要外送前脱敏**（自查第 9 条），对应待办 0-8。04 的工具结果里全是企业名称，这一项从"可选"变成"必须"。
5. **评级档位**：只能从输入数据（`risk_level_summary` 的取值集合）和题目示例里确认档位名称，不得从答案文件推。
6. **额度口径**：输出是区间（如"下限-上限"）或 0；需要定测算公式并全部写进配置（见第四节）。

## 四、方案

### 4.1 多 Agent 编排（建议，写成 ADR-0008）

```
                       ┌─ 工商核验 Agent ─┐
用户 / 申请编号 → 主控 Agent ─┼─ 财报解析 Agent ─┼→ 反欺诈 Agent → 风险评级 & 额度 Agent → 报告 Agent → 输出合规 → 结果
   (意图识别、拆任务)        └─ 舆情扫描 Agent ─┘
自然语言追问：主控按意图只调用需要的角色（如"资产负债率是多少"只走财报解析）
```

- 每个角色 = LangGraph 的一个节点：自己的 system prompt + 工具白名单 + 结构化输出（JSON）。三个采集角色可以并行，缩短到 30 秒内。
- **数字由工具算，模型只负责解释与成文**：所有指标、规则命中、评分、额度都来自确定性工具并落证据；模型写"维度分析结论"和报告段落，不改数字。这正是评审要看的"规则与大模型的融合方式"。
- 主控 Agent 复用现有底座：意图识别、澄清、记忆（"该企业"指代）、输入输出合规、审计、LLM 调用审计。

### 4.2 工具（`@register_tool`，均返回证据）

| 工具 | 做什么 | 主要配置 |
|------|--------|----------|
| `get_loan_application` / `find_enterprise` | 按申请编号、企业编号、企业名称（精确 + 唯一模糊）定位 | — |
| `verify_business_info` | 工商核验：经营状态、法人失信 / 限高、实缴比例、实控人与第一大股东一致性、关联企业数与明细是否一致、对外担保逾期、担保圈 | 阈值 |
| `analyze_financials` | 近三年科目与指标：资产负债率、净利率、ROE / ROA、营收与净利增速 / CAGR、经营现金流 / 净利润、应收与存货周转（次 / 天，营收口径）、总资产周转、有息负债、期间费用率、研发占比；**勾稽校验**：资产 = 负债 + 所有者权益 | `metrics.yaml`：公式、口径、警戒线 |
| `scan_public_opinion` | 舆情事件 + 涉诉：标签（司法执行 / 行政处罚 / 经营负面…）、按类型 × 影响程度 × 情感 × 时间衰减打分；未结案 / 被执行 / 被告金额 | `opinion.yaml`：权重 |
| `detect_fraud_signals` | 规则：营收与经营现金流背离、存货异常增长、应收增速 > 营收增速、其他应收款占比偏高（关联方占款）、净利与现金流长期背离、关联企业多且担保圈；每条输出规则编号、命中值、阈值、置信度 | `fraud_rules.yaml` |
| `rate_risk` | 评分卡：财务、偿债、经营稳定、司法舆情、反欺诈五个维度加权 → 风险档位；一票否决项（失信、限高、逾期未结、严重欺诈信号） | `scorecard.yaml` |
| `calc_credit_limit` | 额度：多口径上限取小（营收 × 系数、净资产 × 系数、经营现金流覆盖、申请额），减存量贷款与或有负债，× 评级系数；高风险 → 0；输出区间、期限、利率浮动方向、担保方式、风控条件，以及每一步的依据 | `credit_model.yaml` |
| `build_dd_report` | 汇总五部分报告结构（数字来自上面工具），供报告 Agent 成文与前端渲染 | — |

配置统一放场景包目录 `ocft-backend/scenarios/dd04/`（README 写明路径）；改阈值不改代码，支持重载。

### 4.3 数据与存储

- 新迁移：10 张业务表（字段与 csv 一致）；导入脚本从 csv 幂等装载，`schema_relationships` 写进表注释与文档；`sql_query` 白名单加入这 10 张表（不含 `question_public` 与答案文件）。
- 非公开集：现场给的是"另一批企业样本"，需要支持**把新 csv 追加导入**后直接跑（导入命令 + 批量测评一条命令串起来）。

### 4.4 评测与导出

- 批量入口：输入 `loan_application.csv`（或现场给的同结构文件）→ 每笔申请跑全链路 → 输出 6 列结果 csv（`utf-8-sig`），列名与答案文件一致；`scoring_points` 由系统自评覆盖了哪些要点。
- 自测比对：风险评级逐条一致、额度区间一致 / 重叠、要点覆盖数；`question_public` 的 10 问做覆盖率；只在 `eval/` 内读答案。
- 耗时统计：每笔 ≤ 30 秒为目标。

### 4.5 前端

尽调工作台：选择申请 / 企业 → 一键尽调（展示六个角色的进度与轨迹）→ 报告页五部分（财务三年表格 + 趋势图、风险与反欺诈线索带规则编号、额度测算依据逐步展开）→ 右侧自然语言追问。导出报告（md / pdf，脱敏）。三张必交截图直接从这里截。

### 4.6 不做清单（建议）

PDF / OCR、图数据库、外部工商接口、RAG 与向量检索（2026-10-24 团队确认本题不用）、多租户与登录、放款流程。
