# 技术选型：后端语言与前端框架

> 状态：生效（2026-10-22 团队确认，前端已按本文落地）。日期：2026-10-21。对应 [开发流程](../10-strategy/开发流程.md) 第 ① 步，决策记录见 [ADR-0001](adr/0001-后端语言与前端框架.md)。
> 前提：项目从零自研，只看技术本身与比赛约束是否匹配。
> 结论：**后端 Python 3.11+ + FastAPI；前端 React 19 + TypeScript + Vite + Tailwind + shadcn/ui（含 AI Elements）+ Motion + ECharts。**

## 1. 选型依据

| 约束 | 对选型的要求 |
|------|-------------|
| 赛时约 26 小时（周六上午 → 周日 12:00） | 生态成熟、现成库多，赛时不造轮子 |
| 主力靠 AI Coding（Cursor / Codex / Kiro） | AI 生成代码质量高、示例多的技术 |
| 必须代码实现 Agent，作品要能证明自研 | 选通用语言与底层库；调度可交给代码形态的图框架，模型与业务逻辑仍自己写；不依赖任何 Agent 平台 |
| 运行时模型 `deepseek-v4.1-flash`（OpenAI 兼容协议） | 各语言都有 SDK，不构成区分 |
| 本地一键启动全栈 | 运行时组件越少越好 |
| 赛题数据形态未知（表格、文档、文本都可能） | 数据处理能力强 |
| 评分：正确率 + 工程完善度 + 合规 + 演示 / 交互 | 后端重数据与可观测，前端重 Agent 过程可视化 |

## 2. 后端语言

### 对比

| 维度 | Python + FastAPI | TypeScript + Node（Hono / NestJS） | Java + Spring Boot | Go |
|------|------------------|-----------------------------------|--------------------|----|
| Agent / LLM 生态 | ⭐⭐⭐⭐⭐ 主流框架、MCP SDK、评测工具都先出 Python 版 | ⭐⭐⭐⭐ 完善，部分能力滞后 | ⭐⭐⭐ Spring AI 可用 | ⭐⭐ 偏弱 |
| 数据处理（CSV / Excel / PDF / 财报文本） | ⭐⭐⭐⭐⭐ pandas、openpyxl、pdfplumber | ⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 金融计算精度 | ⭐⭐⭐⭐⭐ 标准库 `Decimal` | ⭐⭐ 需第三方库 | ⭐⭐⭐⭐⭐ BigDecimal | ⭐⭐ 需第三方库 |
| 接口自描述 | ⭐⭐⭐⭐⭐ 自动生成 OpenAPI 与 `/docs` | ⭐⭐⭐ 需额外配置 | ⭐⭐⭐ 需额外配置 | ⭐⭐ |
| 类型安全 | ⭐⭐⭐ type hints + Pydantic 运行时校验 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 开发速度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ 样板代码多 | ⭐⭐⭐ |
| AI 生成代码质量 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| 前后端同语言 | ✗ | ✓ 可共享类型 | ✗ | ✗ |
| 一键启动复杂度 | 低（venv + pip） | 低（npm） | 高（JDK + 构建） | 最低（单二进制） |
| 性能 | 够用（瓶颈在模型调用） | 够用 | 够用 | 最好，但用不上 |

### 结论：Python + FastAPI

1. **Agent 生态最全**：主流 Agent 框架、MCP SDK 都先出 Python 版，第三方对比普遍认为 Python 在 Agent 与数据管线上领先（[markaicode](https://markaicode.com/usecases/typescript-for-ai-agents/)）。赛时临时接检索、文档解析、计算工具，现成的底层库最多。
2. **数据处理是金融赛题的刚需**：赛题很可能给表格或文档，Python 处理这类数据最快、最稳。
3. **金额精度有标准库**：`Decimal` 不依赖第三方，规则引擎和计算工具可以直接给出可复核的结果。
4. **工程可见性**：FastAPI 自动生成 OpenAPI 文档，Pydantic 校验所有输入输出，评委打开 `/docs` 就能看到完整接口，直接对应"Agent 工程架构完善度"。
5. **AI 写得准**：Python 是 AI Coding 工具最擅长的语言之一。

**TypeScript 全栈是真正的备选**：前后端同语言、类型共享是实打实的好处。没选它，是因为它在数据处理和 Agent 周边库上弱于 Python，而这两项对金融赛题的正确率影响更大。前后端类型一致的问题，用 `/contracts` 契约加前端 TypeScript 类型来补。

**劣势与应对**：类型约束弱 → 全量 type hints + Pydantic；前后端两种语言 → 契约先行，前端只认 API。

## 3. 前端框架

### 对比

| 方案 | 交互上限（炫） | 赛时出活速度 | Agent 界面组件 | 一键启动 | 适合本项目 |
|------|---------------|-------------|---------------|---------|-----------|
| **React + TS + Vite + shadcn/ui** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ shadcn AI Elements 官方提供 | 简单，纯静态开发服务 | ✅ 推荐 |
| Next.js（React） | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 多一个 Node 服务端 | SSR / 服务端组件用不上，后端已是 FastAPI |
| Vue 3 + Vite + Naive UI / Element Plus | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ Agent 专用组件少 | 简单 | 可行，但 Agent 组件生态弱 |
| Svelte / SvelteKit | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ | 简单 | AI 生成质量与组件生态不如 React |
| Streamlit / Gradio（Python） | ⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | 最简单 | 交互上限低，观感像 Demo，主观分吃亏 |

### 结论：React 19 + TypeScript + Vite + Tailwind，组件层用 shadcn/ui

| 组成 | 用途 | 选它的理由 |
|------|------|-----------|
| React 19 | UI 框架 | 生态最大，AI 生成质量最高，Agent 界面组件最多 |
| **TypeScript** | 语言 | 从零开始就该用：与后端契约类型对齐，AI 改代码时有类型兜底 |
| Vite | 构建与开发服务 | 启动快、配置少，只是一个本地开发服务，一键启动最简单 |
| Tailwind CSS | 样式 | 与 shadcn/ui 配套，AI 写样式最快 |
| **shadcn/ui** | 基础组件 | 组件源码直接复制进本仓库，归我们所有、可任意修改，不是黑盒依赖 |
| **shadcn AI Elements**（Trace、Tool、Plan 等） | Agent 执行过程 | 2026-10 shadcn 官方发布，Trace 专门展示 Agent 的每一步与状态（[shadcn 更新日志](https://ui.shadcn.com/docs/changelog/2026-10-ai-elements)），对应我们的工具轨迹与证据链 |
| Motion | 动效 | 轨迹逐步出现、证据展开、状态切换 |
| ECharts | 图表 | 金融图表齐全、中文生态好，用于展示业务价值数据 |

**"炫"的方向**：不做花哨落地页，而是把 Agent 的执行过程做成可视化，包括逐步亮起的工具轨迹、可点开的证据快照、醒目的合规拦截、业务确认的留痕时间线。这同时服务三个评分点：交互体验、演示完整度、"可审计的自研 Agent"这个差异化卖点。

**不选 assistant-ui 等完整聊天框架**：它们自带消息运行时，会接管对话状态。用 shadcn 的组件源码，界面层和数据流都由我们自己掌控，也更容易说明"自研"。

## 4. 与"自研"的关系

比赛禁止的是用扣子等平台**拼装 Agent**，允许使用语言、框架与公开组件。我们的边界是：

| 自己写（作品核心） | 用现成的（通用基础设施） |
|-------------------|------------------------|
| Agent 终态、轮数 / 时限 / token 上限、上下文策略 | 编程语言、Web 框架（FastAPI / React）；LangGraph 1.2.16 只调度下一跳（[ADR-0004](adr/0004-用LangGraph封装有界工具循环.md)） |
| 工具注册、参数校验、证据与审计 | ORM（SQLAlchemy）、校验库（Pydantic） |
| 合规规则、业务规则引擎 | 模型 SDK（openai，只用于发 HTTP 请求） |
| 契约、数据表结构、前端交互与可视化 | UI 组件源码（shadcn，复制进仓库后自行修改） |

编排调度使用 LangGraph：`app/agent/graph.py` 只决定下一步是调用模型还是执行工具。终态、上限、工具协议和证据事务仍是本仓库代码。不使用框架自带的 ChatModel、ToolNode 或 checkpointer，也不引入 CrewAI、AutoGen 或完整 LangChain 包。完整依赖清单见 [自研边界与依赖清单](自研边界与依赖清单.md)。
