# 0008 赛题 04 采用主控 + 六角色多 Agent 编排

状态：已采纳    日期：2026-10-24    提出方：Agent 核心（王小文拍板）

部分取代 [0005](0005-单主Agent不做多Agent.md)：只在 `enterprise_dd` 场景内取代。0005 的其余约束不变：模型只经 `app/llm.py` 调用，工具只经注册表，服务层单事务落库。

## 背景

赛题 04 的提交材料说明（2.2 第 5 条、2.3 第 1 条）要求写出「多 Agent 角色划分与编排配置路径」和「多 Agent 架构图」，模块分工表也要求「主控 + 6 个角色节点，采集三角色并行」。当前实现是单个主控 Agent 依次调用 9 个工具，撑不起上述描述。旧的全局 6 轮 / 60 秒限制会截断这种调用，而官方规则并没有这项要求。

同时，`enterprise_risk.risk_level_summary` 与公开测评集的评级 10/10 一致。在旧实现中，它会通过 `rate_risk` 的 `externalRiskLevel` 字段送进模型，还被用来判断是否需要人工复核，也会出现在目录接口和 `sql_query` 的结果里。

## 决策

用一张 LangGraph 图编排 1 个主控 Agent 和 6 个角色 Agent。当前 `parallel_analysis=true` 的执行顺序如下：

1. 主控做意图识别、定位对象，然后规划本次需要哪些角色。
2. `prepare` 装配一份只读快照，并对敏感字段做代号化。
3. 按 `business`、`finance`、`opinion` → `fraud` → `rating` 的依赖顺序完成五个角色的确定性计算。
4. 工商、财报、舆情、反欺诈和评级授信五个角色并行调用模型生成解读；反欺诈和评级解读只读取已算出的上游结构化事实，不等待上游文字。
5. 报告角色在五个解读完成后汇总（单项追问时改由主控成文）。
6. 事实校验器检查（纯代码），然后由 engine 判定终态。

`parallel_analysis=false` 时按依赖顺序逐级计算并解读。每个角色的数字都来自 `dd_calc` 纯函数，模型只输出结构化解读，不能改动数字。角色划分、依赖关系、并行开关、每个角色的 max_tokens 和提示词放在 `ocft-backend/scenarios/dd04/agents.yaml`。

5 项拍板（2026-10-24）：

1. **外部汇总评级**：运行时彻底不读 `risk_level_summary`。工具结果、证据、目录、提示词里都不出现；`sql_query` 显式引用该列时拒绝执行，`SELECT *` 时从结果里剔除。一致性对照只在 `eval/` 里做。
2. **角色模型调用**：首版 6 个角色全部开启模型分析。真实模型联调后，如果耗时超出目标，可在 `agents.yaml` 里按角色关闭，不需要改代码。
3. **角色补查**：首版不开放。`prepare` 一次性预取完整，角色节点不访问数据库 Session。
4. **运行限制**（2026-10-24 修订，取代初稿的「180 秒 / 14 次调用场景预算」）：比赛规则和赛题 04 都没有轮数或总时限要求。全局默认改为**不限工具循环轮数、不限 run 总时长**（`run_max_tool_rounds` / `run_timeout_seconds` 默认 `None`，需要时可用环境变量重新启用）。保留两道兜底：一是 run 累计 token 上限，二是单次模型调用超时 `llm_timeout_seconds`。30 秒只作为统计目标，不作为终止条件。
5. **名称与隐私**（2026-10-24 修订）：用户问题、消息与会话标题在持久化前隐藏库内已知自然人名称，企业名称可保留；外送主控和角色模型的内容使用同一 run 代号映射。最终回答与澄清问题在输出合规检查和发布前只还原本次 run 登记的企业/机构名称，自然人显示为保留姓的脱敏形式（张三 → 张*，2026-10-25 修订），信用代码、证件号和地址不还原；接口输出历史回答时同口径修复旧版误遮罩（****01-1）与早期全名，库内原文不改写；导出沿用独立脱敏规则。工具参数只在本地执行前还原，模型审计预览保持脱敏。

## 后果

- **好处**：
  - 角色、依赖和每个角色的模型调用都有真实轨迹，可以直接画架构图，也能写清配置路径。
  - 数字由纯函数计算，同一输入两次结构化结果完全一致。
  - 答案列从运行时彻底隔离。
- **代价**：
  - 模型调用从单主控扩展为主控、五个并行分析解读和报告汇总，token 消耗与失败点增加；实际耗时必须按冻结版本测量，不用角色数估算 SLA。
  - 不限轮数和总时长后，失控循环只靠 token 上限截停，单次卡住只靠单次调用超时截停，因此 token 上限不能取消。
  - 需要新增图、快照、校验器，事件记录器要加锁。
  - 并行节点禁止使用 Session，补查能力暂时缺失。
- **何时重访**：
  - 真实模型下 P90 明显超过 30 秒目标：先关闭三路采集角色的模型分析，仍不够再合并评级与报告调用。
  - 评测中出现 run 长时间不结束或 token 失控：重新启用 `RUN_MAX_TOOL_ROUNDS` / `RUN_TIMEOUT_SECONDS`。
  - 非公开集出现快照预取覆盖不到的数据：再评估开放角色补查。
