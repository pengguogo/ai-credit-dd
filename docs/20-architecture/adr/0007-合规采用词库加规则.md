# 0007 合规采用本地词库 + 规则，不接第三方内容安全 API

状态：已采纳    日期：2026-10-22    提出方：合规与可观测

## 背景

合规是强制项：输入和输出都要过滤敏感内容，拦截要留痕。可选方案有两类：调用云厂商的内容安全 API，或在本地用词库和规则判断。提交包要求离线可运行，评测时网络和第三方账号都不一定可用；把用户问题和答案发给第三方，还要在"数据使用与脱敏说明"里单独交代。

## 决策

在 `app/compliance/checker.py` 里本地实现：

- 分类词库放在 `app/compliance/lexicon/*.txt`（政治、色情、辱骂、违法犯罪、隐私），合规负责人改词不改代码；`allowlist.txt` 放"反洗钱"这类业务术语，避免误拦。
- 需要看语序的情况用正则规则：提示注入、探测评测标签、查他人隐私（输入端）；违规金融承诺、泄露评测标签（输出端）。承诺类规则按分句排除否定语境。
- 输入命中时 run 直接终态 `blocked`，不调用模型；输出命中时不发布答案。给用户的话术固定，而且不含命中原词；命中原因只写审计。
- PII 由 `pii.py` 脱敏。

## 后果

- 好处：不依赖网络和第三方账号，离线可跑；判定结果确定，同一输入每次一致；数据不出本机；拦截原因可在审计里逐条查到。
- 代价：关键词和正则不理解语义，拆字、谐音、隐喻会漏，正常表述也可能误拦。我们不宣称有完整的合规判定能力，赛时靠公开题和拦截率样例集补词库。
- 重访条件：赛题或主办方明确要求某种内容安全服务，或拦截率样例集显示词库方案漏拦明显且补词无效时，再评估引入模型二次判定（仍只用 `deepseek-v4.1-flash`）或第三方 API，并另写 ADR。
