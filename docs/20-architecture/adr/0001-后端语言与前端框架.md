# 0001 后端语言与前端框架

状态：生效（2026-10-22 团队确认）    日期：2026-10-21    提出人：—

## 背景

项目从零搭建金融 Agent。约束：赛时约 26 小时、依赖 AI Coding、必须代码实现 Agent、本地一键启动、赛题数据形态未知。详细对比见 [技术选型文档](../技术选型-开发语言与前端.md)。

## 决策

- 后端：Python 3.11+ + FastAPI + SQLAlchemy + Pydantic。
- 前端：React 19 + TypeScript + Vite + Tailwind + shadcn/ui（含 AI Elements）+ Motion + ECharts。

## 备选与放弃理由

- TypeScript 全栈：同语言、共享类型，但数据处理与 Agent 周边库弱于 Python。
- Java / Go：样板多或 AI 生态弱。
- Next.js：SSR 用不上，多一个服务端。
- Vue / Svelte：Agent 界面组件生态弱。
- Streamlit / Gradio：交互上限低。

## 落地说明（2026-10-22；2026-10-24 复核）

- shadcn/ui 选用 `base-nova` 风格（Base UI 底座），组件源码在 `ocft-starter/src/components/ui/`。
- 最终未引入 AI Elements 或 AI SDK 依赖；Agent 轨迹使用仓库内的本地 `Trace` 源码组件，直接映射后端 SSE 事件。
- 最终未引入 ECharts；报告图表由 `ocft-starter/src/components/report/preview/report-charts.tsx` 直接生成 SVG / HTML。
- TypeScript 7.0.2；`npm run build` 先 `tsc -b` 类型检查再构建。

## 后果

- 好处：数据处理和 Agent 生态最强；前端有官方 Agent 轨迹组件，便于做过程可视化。
- 代价：前后端两种语言，需靠 `/contracts` 维护类型一致。
- 重访条件：赛题以纯对话、无数据处理为主，且前后端类型不一致频繁出错。
