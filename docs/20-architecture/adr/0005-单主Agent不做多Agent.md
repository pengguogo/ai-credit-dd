# 0005 单主 Agent，不做多 Agent 协作

状态：已采纳；`enterprise_dd` 场景部分取代（by [0008](0008-赛题04采用主控加六角色多Agent编排.md)，2026-10-24）    日期：2026-10-22    提出方：Agent 核心

## 背景

赛题抽签后才公布，赛时约 26 小时。评分看正确率、编排与可观测性、合规，所有结论都要能追溯到证据。多 Agent（规划者、执行者、审核者互相对话）会让每次 run 的模型调用次数和 token 成倍增加；出错时也要在几个 Agent 的对话里找是哪一步出了问题，单次 60 秒的时限和证据链都更难保证。

## 决策

每次 run 只有一个主 Agent，按 `scenario_id` 加载 `Scenario(system_prompt, allowed_tools, confirmation_rules)`，在有界工具循环里调用工具（调度见 [0004](0004-用LangGraph封装有界工具循环.md)）。"多场景"靠场景注册表切换，不靠多个 Agent 互相调用。需要分工的环节由代码承担：业务结论由规则工具计算，合规由 `app/compliance/` 在模型前后检查，终态由 `engine.py` 判定。

## 后果

- 好处：一次 run 只有一条轨迹，证据、耗时、token 都能直接对应；轮数和时限只在一个地方控制；换赛题只改场景包。
- 代价：没有多角色交叉审核，复杂任务全靠单个 Prompt 和工具设计；同一问题跨多个场景时，需要用户切换场景或在一个场景里放更多工具。
- 重访条件：评测归因显示错误主要来自单 Agent 规划能力不足（不是工具或数据问题），且时限和费用允许时，再评估"规划 + 执行"两段式，并另写 ADR。
