# 尽调口径区分（企业 / 本笔贷款）需求

状态：已实现    负责人：Agent核心、场景与文档、数据层与工具、前端

## 变更
- 2026-10-25：用户要求主控判断「针对企业的尽调」还是「针对某笔放款的尽调」，两类报告分开；企业口径不出现「申请贷款额度」。同步 design、tasks 1–9、TC-1–TC-10。
- 2026-10-25：用户追加要求——针对某笔放款的尽调报告，尽调结论要先明确结论、再给支撑原因。新增需求 5，同步 design「结论顺序」、tasks 10、TC-11–TC-12。
- 2026-10-25：用户复核后追加——企业口径结论改成合作建议（建议合作 / 审慎合作 / 暂不合作）；正文不得残留申请额度、放款/投放等贷款申请措辞，出现即按事实校验重写。同步 design「口径拦截」、tasks 11、TC-13–TC-15。
- 2026-10-25：用户明确——企业尽调仍要「建议授信额度」（能力测算），只要不要「申请贷款额度」；报告保持五部分。同步本文件与 design / tasks / test-cases / 契约。

## 背景
当前 `run_dd_agents` 只给企业编号时会静默取该企业最近一笔贷款申请，报告固定写成某笔贷款尽调并出现「申请贷款额度」。企业档案入口发起的主体尽调不应绑定某笔申请额，但仍需给出基于主体能力的「建议授信额度」。

## 用户故事与验收标准
1. 作为主控 Agent，我希望先判断尽调口径，再调度角色。
   - WHEN 问题指向某笔贷款申请（给出申请编号，或提到本笔贷款 / 放款 / 申请额度 / 期限 / 担保）THEN 主控 SHALL 使用 `scope=loan`，报告保持五部分并含额度建议。
   - WHEN 问题只针对企业本身（工商、财务、舆情、涉诉、担保、风险评级）或明确说「企业尽调 / 主体尽调」，且没有指向某笔申请 THEN 主控 SHALL 使用 `scope=enterprise`。
   - IF 传入的 scope 不是 `loan` / `enterprise` THEN 系统 SHALL 返回 `invalid_args`，不调度任何角色。
2. 作为审批阅读者，我希望企业尽调报告含建议授信额度、不含申请贷款额度。
   - WHEN 生成 `scope=enterprise` 的完整报告 THEN 正文 SHALL 包含「企业概况、财务分析、风险提示、额度建议、风控条件」五部分；额度建议与摘要只写「建议授信额度」，全文不出现「申请贷款额度」「申请额度」「放款前」「投放前」「贷款期限」「本次融资」。
   - WHEN `scope=enterprise` THEN 系统 SHALL 按主体能力测算建议授信额度并产出 `calc_credit_limit` 证据（无申请额封顶）；`applyAmount` 为 null；尽调结论 SHALL 先给合作建议（建议合作 / 审慎合作 / 暂不合作）与建议授信额度，再写「依据：」。
   - IF 企业口径正文仍出现申请贷款额度、放款前、投放前、贷款期限等贷款申请措辞 THEN 系统 SHALL 按事实校验拦下并重写；重写用尽仍不通过时不发布正文，返回 `narrative_check_failed`。「建议授信额度 / 额度建议」允许出现。
   - WHEN `scope=loan` THEN 报告 SHALL 保持现有五部分（含额度建议）与「申请贷款额度 / 建议授信额度」并列口径。
3. 作为客户经理，我希望报告存档和预览与口径一致。
   - WHEN 企业口径报告完成 THEN 系统 SHALL 照常建档，标题用企业编号，`applyAmount` 为 null，不推进任何贷款申请状态。
   - WHEN 打开报告预览或导出结构化报告 THEN 企业口径报告 SHALL 展示建议授信额度 KPI 与额度建议章节，不展示申请贷款额度。
4. 作为评测负责人，我希望公开测评集口径不变。
   - WHEN 输入包含申请编号 THEN 系统 SHALL 走 loan 口径，公开 10 笔申请的风险评级、建议额度与五部分结构不受影响。
5. 作为审批阅读者，我希望贷款口径报告先给结论再给理由。
   - WHEN 生成 `scope=loan` 的尽调结论 THEN 第一句 SHALL 明确准入建议（建议准入 / 审慎准入 / 暂不准入）及建议额度、期限，随后用「依据：」列 1–3 条支撑事实；不得先罗列评级、财务数字再下结论。
   - WHEN 额度无法测算 THEN 结论 SHALL 仍先给准入建议，并写明额度无法测算、需补充材料复核，不编造额度。
   - WHEN `scope=enterprise` THEN 尽调结论 SHALL 先给合作建议与建议授信额度再写「依据：」，不得写成贷款准入结论，也不得出现申请贷款额度。

## 不做什么
- 不改评分卡、额度公式与阈值；企业建议授信额度沿用既有能力测算路径（无申请额封顶），不另立企业级授信政策开关。
- 不改五步单页（仍按所选贷款申请出报告）；不改评测集、答案与离线比对口径。
- 不为「企业口径是否需要额度」增加用户开关；口径由主控按问题判断，工具按入参兜底。
