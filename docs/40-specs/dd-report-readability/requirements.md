# 报告结论分层、业务用语与依据定位

## 变更
2026-10-25：用户确认依次实施优化项 2、3、4。
## 背景
报告生成成功容易被理解为贷款获批；正文夹杂内部字段；结论缺少就地查看依据入口。
## 用户故事与验收标准
- R1：WHEN 查看报告或追问是否通过，THEN 分清生成状态、尽调建议与实际审批，审批只引用贷款申请状态且标明快照时间；缺失则明确未知。
- R2：WHEN 展示业务正文，THEN 用业务语言说明预警与资料缺口，不展示 flag、needsManualReview、布尔值；数字、原始证据和既有报告存储不改写。
- R3：WHEN 点击关键结论的查看依据，THEN 定位本次运行、同一申请/企业的真实证据，展示来源、版本、时间、计算口径与快照；没有匹配证据时不生成链接。
## 不做什么
不修改评级/额度规则，不代替授信审批，不新增写操作或 API，不重写历史存储。

## 2026-10-25 后续展示调整（以此为准）
用户要求从 HTML 报告移除首页“报告生成 / 尽调建议 / 贷款审批”三块与末页“报告依据与生成时快照”。对应报告内证据链接与目录入口一并移除，保留七章正文、数值、业务用语及系统已有轨迹/证据存储；对话中的状态区分继续保留。R1 的三块展示与 R3 的依据附录不再适用于 HTML 报告。
