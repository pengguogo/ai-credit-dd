# 报告列表（资产档案） 需求

状态：已实现    负责人：Agent 核心 / 前端 / 场景与文档

2026-10-25 状态梳理变更：报告不再有状态（不做确认 / 驳回 / 归档），贷款申请状态统一为四态，已实现。

## 背景
官方赛题 04 的评审维度②要求「会议与资产管理：能对任务、待办与产出物（尽调报告、证据材料）进行建档、检索、状态跟踪与归档，形成完整闭环，而不是静态展示」。AI 评委扫描在 `eea0d32` 上该项扣 12 分，理由是「评测路径未端到端覆盖」。当前已有会话、记忆、证据与报告导出，缺的是从尽调任务到报告的可检索档案。

2026-10-25 用户明确：**报告是产出物，本身不需要状态**。确认 / 驳回 / 归档不再做；审核结论只记在贷款申请上（待处理 → 待审核 → 审核通过 / 审核不通过）。

## 用户故事与验收标准
1. 作为复核人员，我希望每次完成的尽调都有可检索的报告档案。
   - WHEN 一个 run 完成且正文是完整五部分尽调报告 THEN 系统 SHALL 自动建档一次，记录 `runId`、申请/企业、摘要、证据条数与内容哈希。
   - IF run 失败、澄清、追问答案或非完整报告 THEN 系统 SHALL 不建档，不制造空档案或把问答当产出物。
2. 作为复核人员，我希望按对象找到报告。
   - WHEN 检索 THEN 系统 SHALL 支持关键词（标题 / 申请 / 企业 / 摘要）、企业、申请过滤，并保持分页与计数一致。
   - IF 报告需要确认或驳回 THEN 系统 SHALL 不提供该操作；审核结论只通过贷款申请状态（待处理 / 待审核 / 审核通过 / 审核不通过）体现。
3. 作为交付负责人，我希望能现场演示建档与检索。
   - WHEN 打开「报告列表」页面 THEN 系统 SHALL 展示报告列表、详情与关联报告入口，不展示状态、状态流转或复核操作。
   - WHEN 审计档案 THEN 系统 SHALL 只指向 `runId`，报告正文与证据仍以 run / evidence 为准，不复制出第二份结论。
4. 作为业务用户，我希望用企业名称识别档案，不需要理解内部运行标识。
   - WHEN 展示新旧档案 THEN 系统 SHALL 从企业事实表获取中文企业名称，标题优先显示「企业名称 · 信贷尽调报告」；企业名称缺失时明确提示未登记，不编造名称。贷款申请保留带中文标签的业务编号，支持按企业名称检索。
   - WHEN 查看列表与详情 THEN 系统 SHALL 用中文说明生成信息，不展示 `run`、`runId`、运行编号和英文状态码；企业名称与申请编号在详情中分行展示，报告链接仍指向原始报告。
5. 作为业务用户，我希望贷款申请状态清楚。
   - WHEN 尽调报告生成 THEN 系统 SHALL 把该申请从「待处理」推进到「待审核」（已审核的申请不覆盖）。
   - WHEN 人工审核 THEN 系统 SHALL 只能得到「审核通过」或「审核不通过」，不出现第五种状态或聚合筛选项。

## 不做什么
- 不做会议纪要、日历、日程或人员分派系统；「会议与资产」在本赛题落地为任务 / 产出物档案与检索。
- 报告不设状态：不做确认、驳回、归档、重新打开，也不保留状态筛选项与状态流转记录。
- 不复制报告正文到档案表，不做第二套结论来源。
- 不以报告状态替代业务签核；审核结论记在贷款申请状态。
- 不做跨租户权限体系；沿用现有登录角色。
