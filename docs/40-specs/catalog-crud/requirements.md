# 数据列表维护（导入入口 + 增删改查）需求

状态：已实现    负责人：数据层 + 前端；契约协同 Agent 核心统筹

## 变更
- 2026-10-24：写操作需具备 `catalog_write`；无该权限时列表只读（交叉 auth-admin）。同步：tasks 完成标准补充。
- 2026-10-24：新建。上传入口从工作台「业务数据」迁到「数据列表」；每张可导入业务表支持本表 CSV 导入；列表支持单行新增、编辑、删除（读沿用现有目录接口）。
- 2026-10-24：`schema_relationships`（表关系）不支持导入与增删改，前端用流程节点图只读展示主从表关系。
- 2026-10-24：用户确认可写业务表支持单行更新/删除（突破 CSV 导入「只新增」边界；导入接口语义不变）。

## 背景
工作台业务数据面板只适合选企业/申请填对话。数据列表应成为导入与维护入口。CSV 导入仍仅新增；单行维护走新写接口。

## 用户故事与验收标准

1. 作为数据维护人员，我希望在数据列表维护业务表。
   - WHEN 打开除「表关系」外的业务表 THEN 系统 SHALL 提供「导入」「新增」，每行提供「编辑」「删除」。
   - WHEN 打开工作台业务数据面板 THEN 系统 SHALL 不再展示 CSV 上传入口。

2. 作为数据维护人员，我希望只导入当前表的 CSV。
   - WHEN 在某可导入表提交对应白名单文件名 THEN 系统 SHALL 走现有 `POST /api/agent/data/imports` 仅新增语义。
   - IF 文件名不属于当前表 THEN 系统 SHALL 在提交前拒绝。

3. 作为数据维护人员，我希望对单条业务记录增删改。
   - WHEN 调用方具备 `catalog_write` 且新增业务键不冲突 THEN 系统 SHALL 插入；冲突 409。
   - WHEN 按内部 `id` 编辑/删除 THEN 系统 SHALL 更新或删除；不存在 404；唯一冲突 409。
   - WHEN 列表加载可写表 THEN 系统 SHALL 在每行返回 `id`（可不作为展示列）；取值仍 PII 掩码。
   - 写操作 SHALL 追加审计，不调用模型。
   - IF 无 `catalog_write` THEN 前端 SHALL 不展示写操作；写 API SHALL 403。
   - IF kind 为 `schema_relationships` THEN 写接口 SHALL 返回 400，前端不展示写操作。

4. 作为使用者，我希望看清表关系。
   - WHEN 打开「表关系」THEN 系统 SHALL 用流程节点图展示主表→子表关系（数据仍来自目录只读接口），无导入/新增/编辑/删除。

5. 作为界面开发人员，我希望菜单覆盖企业基础信息与既有表。
   - WHEN 打开数据列表 THEN 系统 SHALL 含企业基础信息 + 原 9 表（共 10 项）。

## 不做什么
- 不改 CLI 覆盖导入；不提供批次隔离。
- 不在工作台恢复多文件总上传。
- 不对 `schema_relationships` 做写操作或 CSV 导入。
- 不做软删除、批量勾选删除、Excel 式行内编辑。
- 运行时评分卡仍不读 `risk_level_summary` 作结论（ADR-0008）。
