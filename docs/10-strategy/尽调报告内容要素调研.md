# 企业信贷尽调报告内容要素调研

> 目的：梳理银行对公授信尽调报告通常包含的内容，对照本项目数据与五节骨架找出能写什么、缺什么，作为 `dd-report` Skill 优化依据。
> 本文是团队调研整理，不是监管条文；运行时报告不引用这里提到的任何法规名称或条款。

## 1. 尽调报告要回答的三个问题

银行授信尽调与投资尽调不同：投资看"能不能长大"，授信看"会不会倒、钱能不能收回"（[企查查：在银行做尽调，查到哪一层才算够](https://b.qcc.com/portal/information-center/articles/77a03582cdce82ebc87ee0395097c534)）。一份合格的报告围绕三件事展开：

1. 谁在借钱：主体真实、股权穿透到实控人、关联方和担保圈理清。
2. 拿什么还：第一还款来源是经营现金流，报表要和现金流、纳税、流水交叉验证。
3. 还不上怎么办：第二还款来源（担保、抵押）、风险信号和贷后预警。

国际通行的 5C 框架与此对应（[CRI：Credit Memo Best Practices and the 5 C's](https://www.criadv.com/insight/credit-memo-best-practices/)）：品格（履约与公共记录）、能力（偿债覆盖、近 3–5 年现金流）、资本（自有资金与流动性）、担保（押品价值与抵押率）、条件（金额、期限、利率、契约条款与监测方式、资金来源与用途）。

## 2. 常见章节与要素清单

| 章节 | 应包含的要素 | 常用指标 / 判断点 |
|------|------|------|
| 授信申请概要 | 申请金额、用途、期限、担保方式、申请日期；报告编号、数据基准日 | 用途是否与经营匹配，金额是否超出合理需求 |
| 借款人主体 | 名称、信用代码、成立日期、行业、经营范围、经营状态、注册/实缴资本 | 实缴比例；经营状态是否正常；经营异常名录 |
| 股权与实际控制人 | 股东结构、持股比例、出资与实缴；实控人识别；董监高 | 股权穿透到最终自然人或国资主体；实控人与第一大股东是否一致；代持、一致行动 |
| 关联企业与担保 | 关联方清单、关系类型；对外担保金额、方式、期限、是否逾期；担保圈 | 关联方登记与明细是否一致；担保圈、互保链；担保代偿风险 |
| 经营与行业 | 主营业务、上下游、主要客户与供应商集中度、行业周期与政策 | 收入真实性（纳税、流水、水电社保交叉验证） |
| 财务分析 | 近三年资产负债表、利润表、现金流量表核心科目；审计意见；报表勾稽 | 盈利（营收增长、净利率、ROE/ROA）、偿债（资产负债率、有息负债率、流动/速动比率）、营运（应收、存货周转天数）、现金流质量（经营现金流/净利润）、费用结构 |
| 非财务风险 | 涉诉（角色、状态、金额）、失信与限高、行政处罚、负面舆情 | 未结被告案件金额；法定代表人失信/限高；事件时间衰减 |
| 反欺诈 | 财务造假线索与关联欺诈 | 营收与现金流背离、存货异常增长、应收增速高于营收、其他应收款占比高、关联交易占比高 |
| 授信需求与额度测算 | 测算方法、取数年度、关键参数、假设 | 流动资金贷款常用"营运资金需求"思路（销售收入、利润率、周转次数扣减自有资金和他行融资）；本项目用团队模拟政策（营收口径与净资产口径取小，乘评级与现金流系数） |
| 还款来源 | 第一还款来源（经营现金流、主营收入）；第二还款来源（担保、抵押） | 现金流为正且覆盖本息；担保方式与担保能力 |
| 风险评级 | 评分卡结果、各维度得分、一票否决项 | 评级与额度一致；否决项必须单列 |
| 授信方案 | 额度、期限、利率方向、担保方式 | 与评级和测算结果一致 |
| 风控条件 | 放款前条件、贷后监测、预警触发与退出 | 条件要可执行、可检查，对应已识别的风险 |
| 结论与声明 | 准入建议、需人工复核项、数据局限、免责说明 | 结论与数据事实一致；"测算建议，非授信审批" |

监管层面，银行授信尽调要求核查实控人、受益所有人和关联方，并采用现场与非现场结合的方式（同上企查查文章对《商业银行授信工作尽职指引》《流动资金贷款管理办法》的概括）。这些只作背景，报告正文不引用。

## 3. 赛题要求与样例

- 题目要求的五部分：企业概况、财务分析、风险评级、额度建议、风控条件（[题目说明](../00-rules/赛题/赛题04_企业智能信贷尽调/题目说明.md)）。
- 可解释性评审点：指出命中的规则或指标、科目、金额、期间、记录 ID；不确定项标"需人工复核"；同输入多次运行格式不漂移。
- 业务侧抽查：财报口径一致、风险结论与数据事实一致、额度测算依据可解释（用了哪些指标、规则与假设）。
- 主办方样例（[提交材料说明](../00-rules/赛题/赛题04_企业智能信贷尽调/提交材料说明.md) 示例 C）的写法：概况列主体与实控人、失信限高标记；财务表含趋势列；风险提示分条编号；额度建议写测算依据；风控条件含贷后报表与触发复评。

## 4. 本项目映射

报告角色只能拿到各角色的计算精简结果（`dd_roles.brief`）和解读，事实校验（`dd_verify`）会拦下找不到来源的带单位数字。按要素对照如下：

| 要素 | 报告输入里有 | 写进哪一节 |
|------|------|------|
| 经营状态、行业、成立日期 | `report.overview` | 企业概况 |
| 实缴比例、实控人与第一大股东一致性、关联企业登记与明细、担保逾期、担保圈 | `roles.business.brief` | 企业概况 |
| 近三年核心科目、审计意见、报表勾稽、增长率、九项指标与 flag | `roles.finance.brief` | 财务分析 |
| 舆情健康分、标签、事件、涉诉、未结被告金额 | `roles.opinion.brief` | 风险提示 |
| F01–F06 规则结果 | `roles.fraud.brief` | 风险提示 |
| 评分、维度、否决项、需复核 | `roles.rating.brief.rating` | 风险提示 |
| 额度、期限、利率方向、担保方式、测算步骤、取数年度、假设、条件 | `roles.rating.brief.credit` | 额度建议、风控条件 |
| 额度无法测算的原因 | `roles.rating.brief.creditError` | 额度建议 |
| 各角色不确定项 | `roles.*.analysis.uncertainties` | 风控条件（待核实） |

数据缺口（报告不能写，也不得编造）：

- 申请金额、贷款用途、申请日期没有传给报告角色，只能通过额度测算步骤间接体现。要写"申请额 / 用途"需要在 `brief("report")` 增加字段，属于 Agent 核心公共层改动，需先沟通。
- 存量贷款余额、对外担保总额（`exposures`）不在精简输入里，只能引用风控条件里已有的表述。
- 数据集没有营业成本、流动资产细分、应付周转：不写流动比率、速动比率、毛利率、现金周期；周转天数以营业收入为分母，需注明口径。
- 没有纳税、流水、水电社保数据：不做这类交叉验证，也不写"已核实纳税"。
- 企业名称、信用代码、法定代表人都已脱敏，不用"***"占位凑格式。

## 5. 对 dd-report Skill 的优化（1.1.0 → 1.2.0）

1. 企业概况按"主体 / 资本与股权 / 关联与担保 / 核验结论"写，补上实缴比例、实控人与第一大股东一致性、关联企业登记与明细是否一致。
2. 财务分析按"盈利 / 偿债 / 营运 / 现金流质量 / 报表质量"五个维度写要点，表格固定六行，周转天数注明口径。
3. 风险提示固定六条：评级与否决、工商、涉诉、舆情、反欺诈、需人工复核，每条带编号。
4. 额度建议新增"还款来源"与"关键假设"两行；额度无法测算或高风险时如实写，不编数字。
5. 风控条件分"放款前 / 贷后 / 待核实"三类前缀，阈值数字只用输入里出现的。
6. 新增"缺数处理"规则：角色结果缺失时写"未取得…结果，需人工核实"；新增写作前自检清单，降低事实校验重写率。
7. 篇幅上限从 900 字放宽到 1200 字，五节骨架、标题文字、结论用语与免责条款不变，前端导出与单测不受影响。

## 6. 参考版式案例后的 2.0.0

参考团队版式案例（8 页 A4 虚构案例：决策摘要、企业概况、财务趋势、财务质量、风险提示、额度建议、风控条件、证据说明），改为正式报告写法：

1. 开头加决策摘要：五列摘要表、摘要判断、支持因素 / 重点关注、报告边界（尚不能得出的结论）。
2. 五个 `##` 章节下用 `###` 小节，每节"事实表格 → 判断 → 结论边界"三层。
3. 新增表格：主体信息、核验事项与处理意见、三年主要财务数据（13 行）、现金与资产质量、评分维度、敞口摘要、事项时间线、F01–F06 逐条核查、测算路径（照抄 steps）、测算口径、还款来源、贷后管理。
4. 风控条件改为"放款前待核实事项（资料 / 验收 / 关联编号）+ 贷后管理表 + 资料缺口 + 人工复核"。
5. 案例中的自算派生值（期末应收/收入、百分点差）和敏感性测算不采用：事实校验会拦下输入中没有的数字。
6. 篇幅上限 2500 字，报告角色 max_tokens 6000 → 8192。
7. 前端 Markdown 渲染器区分 `#` / `##` / `###` 三级标题样式，表格加表头底色、斑马纹，数字列右对齐。
