# 赛时模块分工表（赛题 04 企业智能信贷尽调）

> 状态：生效（2026-10-24 按当前实现与分工收口）。比赛时间 2026-10-24（周六）至 10-25（周日）。现行需求见 [企业信贷尽调 Spec](../40-specs/enterprise-dd/requirements.md)，架构见 [ADR-0008](../20-architecture/adr/0008-赛题04采用主控加六角色多Agent编排.md) 与 [多 Agent 编排 Spec](../40-specs/dd-multi-agent/requirements.md)；目录归属以 [AGENTS.md](../../AGENTS.md) 为准；规则冲突以 [比赛规则要求](../00-rules/比赛规则要求.md)、[通用提交材料说明](../00-rules/通用提交材料说明.md) 和 [赛题 04 提交材料说明](../00-rules/赛题/赛题04_企业智能信贷尽调/提交材料说明.md) 为准。

## 原则

- 团队 6 人：Agent 开发、数据开发、前端各 1 人，评测、合规提交、文档路演各 1 人；不再单设机动。
- 开发按层切分：王小文负责 Agent（编排、多 Agent、工具、计算、报告生成），胡乾豪负责数据建模与导入，程柳负责全部前端交互与展示。接口按方案设计 §2.2 的交接关系对齐。
- 代码由 AI 生成，不设主程合并人。合入 `main` 前自行跑 `pytest`、红线扫描，有前端改动再跑 `npm run lint`，全部通过后合入。
- **数字由工具算，模型只做解释与成文**。指标、规则、评分、额度一律在工具和配置里实现，不写进提示词（评审看"规则与大模型的融合方式"）；前端不自行计算评级和额度。
- **运行时不读 `risk_level_summary`**。评级由评分卡算出；这一列与公开答案一致，只在 `eval/` 里做一致性对照（[ADR-0008](../20-architecture/adr/0008-赛题04采用主控加六角色多Agent编排.md) 决策 1，2026-10-24 起取代原「只做一致性校验」）。
- **答案文件和 `question_public.reference_answer` 只在 `eval/` 里读**（红线 R4 / R5），评测标签不得回灌运行时。
- 提交物与代码同等重要，由黎锦涛、陈修活、彭国并行准备，不能拖到周日上午。

## 跨模块交接

详见方案设计 §2.2，要点：

1. **数据 → Agent**：胡乾豪交付字段、单位、批次、快照及异常语义；Agent 所需结构变更先交接再由胡乾豪实施迁移。
2. **Agent → 界面**：王小文负责契约与后端行为，程柳负责全部前端；新增字段、阶段事件、错误与受限状态须同步。
3. **开发 → 评测**：王小文、胡乾豪提供可复现入口与版本信息，彭国独立运行、留存证据并反馈差异。
4. **运行 → 文档与提交**：彭国提供统计，程柳提供可用界面，王小文和胡乾豪提供真实路径与限制；黎锦涛整理文档，陈修活合规复核及封包。
