**企业智能信贷尽调 Agent 赛题说明**

面向参赛者发布版

# 一、赛题背景

智能尽调产品已在多家商业银行的贷款业务中落地应用，将企业信贷尽调流程数字化。传统尽调需客户经理上门、收集财报、人工撰写调查报告，耗时 3-5 天，且高度依赖个人经验，存在风控标准不统一、欺诈识别滞后、尽调报告质量参差不齐等问题。本赛题提供一套模拟企业信贷尽调数据集（含企业基础信息、近三年财务数据、风险与舆情信息、贷款申请信息），参赛团队需基于该数据集构建多 Agent 协作的智能尽调系统，在保证风控合规前提下，实现尽调决策的自动化与高效完成。

# 二、任务目标

- 基于官方模拟企业信贷尽调数据集，建立可解析、可核验、可解释的尽调分析层。
- 输入企业基础信息后，自动完成「财报解析 → 工商核验 → 舆情扫描 → 反欺诈检测 → 额度测算 → 尽调报告生成」全链路。
- 支持自然语言问询，能够识别客户经理的尽调问题意图并给出正确结论与依据。
- 识别企业财务异常、关联交易、欺诈线索、舆情风险等尽调异常，并给出可解释分析。
- 输出结构化尽调报告，包含企业概况、财务分析、风险评级、额度建议与风控条件。

【注意】不能直接基于多个csv文件直接做简单LLM应用，要构建Agent系统，支持数据导入、解析、分析、解释、决策、可视化等完整流程。

# 三、必选功能

| 功能 | 要求 |
| --- | --- |
| 财报解析 | 能够解析近三年营收、利润、资产、负债、现金流等核心科目，计算偿债、盈利、营运等财务指标。 |
| 工商核验 | 核验企业基础信息一致性，识别经营异常、关联企业、对外担保等工商风险。 |
| 舆情扫描 | 扫描涉诉、行政处罚、负面舆情，输出舆情风险标签与评分。 |
| 反欺诈检测 | 识别财务数据造假线索（如营收与现金流背离、存货异常、关联交易占比过高）及关联欺诈风险。 |
| 额度测算 | 综合财务指标、风险评级、贷款用途，给出建议授信额度、期限与利率。 |
| 尽调报告生成 | 自动生成结构化尽调报告，含企业概况、财务分析、风险提示、额度建议与风控条件。 |
| 自然语言问询 | 支持客户经理用自然语言追问尽调结论、财务指标、风险点等。 |

# 四、数据说明

本赛题使用官方提供的模拟企业信贷尽调数据集。数据为模拟生成，不涉及真实企业商业秘密或个人信息。参赛团队应基于官方数据包完成开发、演示和自测。

## 测评集说明

- **公开测评集（含标准结果，可自测）**：随参赛资料一并下发，文件为 `公开测试集答案.csv`，含每笔贷款申请的标准尽调结论，**可用于提交前自测**；评委亦会从中现场抽样，要求系统即时处理并与标准结果逐项比对。
- **非公开测评集（只含输入、不含结果）**：**赛前不下发**，现场由评委提供只含输入、不含结果的材料，当场检验系统的泛化能力与新增样本的适配成本。

# 五、交付物

- 可运行 Demo 或在线访问链接，支持输入企业信息后自动完成尽调全链路并在线查看尽调报告。
- 代码仓库或部署包，以及 README / 部署说明。
- 技术方案说明，包含多 Agent 架构、数据导入、财报解析、反欺诈规则、额度测算模型与编排设计。
- 至少 3 个尽调报告截图。
- 系统输出结果文件：公开测评集结果与现场非公开测评集结果（按提交物清单提交）。

# 六、评审要点概述

> 本节只给出评审关注的**四个一级维度**与希望做到的方向。**详细评分标准与分值由评委掌握，不向参赛者公开。**

## 6.1 四个维度的评审要点

| 维度 | 会看什么 | 希望做到什么 |
| --- | --- | --- |
| **① 评测集表现** | 系统在给定企业上的尽调输出：风险评级、建议额度、尽调结论与要点覆盖 | 输出与标准结果一致，能**现场实时重算**；结果是系统跑出来的，而不是预录或硬编码 |
| **② Agent 工程架构完善度** | 记忆系统、会议与资产管理、工具调用能力、Skill 管理四项通用工程能力 | 见下方四条通用要求 |
| **③ Agent 通用评测（鲁棒性、可解释性）** | 异常输入与长任务下的表现，以及结论的推理过程 | 见下方两条通用要求 |
| **④ 合规性** | 敏感数据的处理方式，以及输出内容的合规性 | 见下方两条通用要求 |

**② Agent 工程架构完善度 —— 四项通用要求**

- **记忆系统**：能跨轮次记住已确认结论与口径（如企业风险评级、已核实的财报口径）并在后续任务中正确复用；记忆内容可查看、可纠正、可清除。
- **会议与资产管理**：能对任务、待办与产出物（尽调报告、证据材料）进行建档、检索、状态跟踪与归档，形成完整闭环，而不是静态展示。
- **工具调用能力**：工具选型正确、参数构造准确、无冗余调用；调用失败可诊断并正确重试或降级，返回结果被真正用于影响后续结论。
- **Skill 管理**：能把重复任务（如"解析某一类财报科目""执行某条反欺诈规则"）封装为可复用 Skill／工作流，具备明确的触发条件与输入输出契约，可跨任务迁移复用。

**③ Agent 通用评测 —— 两条通用要求**

- **鲁棒性**：异常输入（字段缺失、口径冲突、极端值、超长或乱序输入、空结果）**不崩溃、不静默出错**；外部调用与长任务有超时控制，超时后明确告知并给出可执行的下一步；失败可自动重试且单点失败不导致整体流程崩盘。
- **可解释性**：结论能给出依据与推理过程——指出命中的规则或指标、涉及的科目、金额、期间、记录 ID；可展示中间过程而非只给答案；对不确定项给出置信度并标注"需人工复核"；同输入多次运行结论一致、格式不漂移。

**④ 合规性 —— 两条通用要求**

- **数据处理合规**：**敏感数据不外送**，确需调用外部大模型或服务时先完成脱敏；界面展示、运行日志与导出文件中的敏感字段同样脱敏，外部调用可审计。
- **输出内容合规**：输出无不当表述，对输入中的不当内容能恰当处理；**法规条款不编造**——政策、法规、条款、标准编号与条文内容不得幻觉生成，更不得以此作为结论依据。

## 6.2 评测集说明

- **公开测评集（含标准结果，可自测）**：随参赛资料一并下发，**含标准结果**，可用于提交前自测；评委亦会从中现场抽样，要求系统即时处理、与标准结果逐项比对，且**可现场实时重算**。
- **非公开测评集（只含输入、不含结果）**：**赛前不下发**，现场由评委提供**只含输入、不含结果**的材料，当场检验系统的泛化能力与新增样本的适配成本。

> **本赛题提示**：非公开测评集为**未参与公开集的另一批企业样本**，现场提供、只给输入不给答案；要求系统对未见样本能快速适配（改配置优于改代码）。

## 6.3 业务侧自查重点

- 尽调环节重点考察**财报口径一致性**与**风险结论与数据事实的一致性**（评委将随机抽条核对）；
- 额度测算重点考察**测算依据的可解释性**（用了哪些指标、规则与假设）；
- 大模型能力不是"调一次 API"，关注 Prompt 设计、规则与大模型的**融合方式**、输出的结构化与稳定性。
