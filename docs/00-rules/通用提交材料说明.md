### 1.1 可运行系统包补充要求：依赖离线内置 + 评测集批量测评调用

> 以下两条为「可运行系统包」的**强制**补充要求，与材料清单第 1 项配套执行；专属说明另有规定的，以专属说明为准。

**（1）依赖必须离线内置，禁止联网下载**

- 系统 zip 包若运行需要第三方库、Python 运行时、模型权重、字体、词典等**任何依赖**，**必须随 zip 包一并提供离线安装包或预装目录**，解压后可在**无外网**环境下完成安装与启动。
- **禁止**在系统 zip 包内、启动脚本里通过 `pip install` / `npm install` / 下载模型权重等"运行时联网拉取"方式获取依赖；评测环境**不保证可联网**。
- 建议做法：包内提供 `wheels/`（离线 whl 包）、`vendor/`（第三方库预置目录）、固化依赖的虚拟环境或容器镜像；README 注明离线安装命令。
- 压缩包解压后根目录应能看到 `README.md`、`manifest.yaml`、源码目录与依赖目录，依赖目录随包一同交付。

**（2）必须提供评测集批量测评调用方式（CLI 或 MCP）**

- 可运行系统包**必须**自带一个用于**评测集批量测评**的标准调用入口，形式二选一：
  - **命令行 CLI**：一条可直接复制执行的命令，批量读入测评输入、批量产出结果；或
  - **MCP 服务**：按 MCP 协议暴露评测调用工具，供评测脚本 / 评委环境对接。
- **输入文件**：支持 `pdf` / `excel(.xlsx)` / `csv` 等格式，可批量遍历输入目录或输入清单。
- **输出文件**：测评结果以 `excel(.xlsx)` 或 `csv` 形式输出（建议 `utf-8-sig` 编码），表头与赛题数据包保持一致。
- README 须给出**批量测评命令 / MCP 启动与调用示例**，并说明输入目录、输出目录、输出文件命名与字段含义；测评集具体形式以该赛题专属说明为准。

**可选但强烈建议**（评审时会作为工程完善度与可审计性的旁证）：

| # | 材料 | 形式 | 说明 |
| --- | --- | --- | --- |
| 7 | 第三方组件 | `.md` / 一并写入 `manifest.yaml` | 逐条列出名称、版本、License、用途、来源链接 |
| 8 | 数据使用与脱敏说明 | `.md` | 说明哪些数据外送、如何脱敏、日志如何留存 |
| 9 | 关键技术难点与权衡说明 | `.md` | 取舍理由、已知局限、后续计划 |

## 二、通用命名规范

### 2.1 团队名

| 规则 | 要求 |
| --- | --- |
| 字符集 | 212 个中文字符，或 ~~2~~24 个英文/数字字符 |
| 禁用字符 | 空格、`/ \ : * ? " < > \|`、制表符、换行符 |
| 一致性 | 团队名在**报名、邮件主题、压缩包名、所有文件名、manifest** 中必须完全一致 |
| 稳定性 | 首次提交后至评审结束**不得改名**；改名需提前书面说明，否则视为两支队伍 |

### 2.2 文件名

**通用模板**：

```
<团队名>_赛题<NN>_<材料名>[_v<主版本>.<次版本>].<扩展名>
```

| 位置 | 取值 | 示例 |
| --- | --- | --- |
| `<团队名>` | 见 2.1 | `星火队` |
| `<NN>` | 两位数字，01~09 | `01` |
| `<材料名>` | 中文短词，同一材料名全包统一 | `技术方案`、`测试报告`、`演示视频`、`团队与元信息表`、`可运行系统包` |
| 版本后缀 | 首次提交**可省略**；替换版必须带 | `_v2.0` |
| 扩展名 | 小写 | `.pdf` `.mp4` `.xlsx` `.md` `.zip` |

**示例（赛题 01 · 星火队）**：

```
星火队_赛题01_技术方案.pdf
星火队_赛题01_技术方案.md
星火队_赛题01_测试报告.pdf
星火队_赛题01_演示视频.mp4
星火队_赛题01_团队与元信息表.xlsx
星火队_赛题01_可运行系统包.zip
```

### 2.3 版本号

- 格式：`v<主版本>.<次版本>`，如 `v1.0`、`v1.1`、`v2.0`
- 内容有实质修订（重跑评测集、更换模型、修复影响结论的缺陷）→ 主版本 +1
- 排版/措辞/补充材料 → 次版本 +1
- 同一团队同一赛题**同时只保留一个当前版本**；旧版本不要放进提交包

### 2.4 日期与时间格式

| 场景 | 格式 | 示例 |
| --- | --- | --- |
| 日期 | `YYYY-MM-DD` | `2026-09-23` |
| 时间 | `HH:MM:SS`（24 小时制） | `14:30:00` |
| 日期时间 | `YYYY-MM-DD HH:MM:SS` | `2026-09-23 14:30:00` |
| 文件名中的日期 | `YYYYMMDD` | `20260923` |
| 时区 | 默认北京时间（UTC+8），跨时区须标注 | `2026-09-23 14:30:00 (+08:00)` |

## 三、通用格式要求

| 类别 | 要求 |
| --- | --- |
| **文档** | PDF（优先）或 Markdown；A4 纵向；正文不小于 10.5pt；单个 PDF ≤ 30MB；**每份 PDF 须同时提供同名 `.md` 源文件**，便于评审检索与复制引用 |
| **编码** | 所有文本类文件统一 **UTF-8**；Markdown / Python / JS / YAML / JSON / JSONL 用 **UTF-8 无 BOM**；供 Excel 直接打开的 CSV 用 **UTF-8 with BOM（`utf-8-sig`）** |
| **代码** | 统一 LF 换行；仓库根目录放 `.gitattributes`（`* text=auto eol=lf`、图片/模型权重等二进制文件标 `binary`）；提供 `requirements.txt` 或 `pyproject.toml` / `package.json`，**锁定具体版本**；依赖须随包提供**离线安装包 / 预装目录**，部署时**禁止联网下载**（见 1.1） |
| **视频** | MP4 封装，H.264 视频 + AAC 音频；分辨率 ≤ 1080p；单个 ≤ 10 分钟；码率 ≤ 8Mbps；单个文件 ≤ 500MB；**不得加密、不得有 DRM、不得加水印遮挡界面文字**；建议附 `.srt` 字幕 |
| **音频**（如需） | MP3 / M4A，≤ 64kbps 之外的清晰音质，单个 ≤ 50MB |
| **截图** | PNG（优先）或 JPG；单张 ≤ 5MB；须为**系统真实界面截图**，不得为设计稿、不得拼接伪造；文件名须能看出对应场景，如 `<团队名>_赛题NN_截图01_<场景名>.png`（场景名以该赛题专属说明列出的场景为准） |
| **表格数据** | 评测集对外输出用 `.csv`（`utf-8-sig`）或 `.xlsx`；多 Sheet 结果用 `.xlsx`；表头用中文且与赛题数据包保持一致 |
| **会话记录** | `.jsonl`，UTF-8，每行一个 JSON 对象，行末 `\n` |
| **压缩包** | `.zip`（优先）或 `.rar`；**单个 ≤ 500MB**；单个压缩包 **≥ 200MB** 时建议线下 U 盘交付（见第八章）；压缩时不要在外层再套一层同名目录（见第六章自查清单第 1 条） |
| **禁止项** | 不得使用分卷压缩、自解压exe、加密压缩包；不得包含 `.git` 目录中的历史大文件（如需提交仓库，改用 `--depth 1` 克隆或导出归档） |

## 四、元信息 manifest 字段规范
