# 启动排障与赛时故障处理

> 按现象查表照做。先看 `GET http://127.0.0.1:8000/api/health/ready`：它会同时报告模型锁定、数据库连通和近期模型调用状态，大部分问题从这里就能定位。
> 密钥相关操作见 [密钥管理](密钥管理.md)。

## 一、一键启动排障

启动命令：`powershell -ExecutionPolicy Bypass -File .\start.ps1`（只支持 Windows）。依赖异常时加 `-Reinstall` 重装。

| 现象 | 原因 | 处理 |
|------|------|------|
| `缺少 python` / `缺少 npm` | 没装或没进 PATH | 装 Python 3.11+、Node.js 18+，重开终端 |
| `Python 版本过低` | 低于 3.11 | 升级 Python 后删掉 `ocft-backend/.venv`，重新启动 |
| `后端依赖安装失败`，日志有 `SSLError` / `UNEXPECTED_EOF` | 访问 PyPI 官方源网络不稳 | 换镜像：`ocft-backend\.venv\Scripts\python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r ocft-backend/requirements.txt`，版本仍以 `requirements.txt` 为准 |
| 后端启动报 `ModuleNotFoundError` | 拉了新代码，`requirements.txt` 新增了依赖，但启动脚本只检查部分关键包 | 用 `-Reinstall` 重新启动，或按上一行手动安装；新增依赖时把包名加进 `start.ps1` 的导入检查 |
| `端口 8000/5173 已被占用` | 上次进程没退出 | `Get-NetTCPConnection -LocalPort 8000 -State Listen` 查 PID，`Stop-Process -Id <PID>` |
| 启动报 `LLM_MODEL 配置为 ...` / `LLM_API_MODEL 配置为 ...` | `.env` 填了非比赛指定模型 | 两项都留空，或 `LLM_API_MODEL` 改成白名单内的值；不得换模型（红线 1） |
| 启动报缺少 `OCFT_MASTER_KEY` 或解密失败 | `.env` 里是 `enc:` 密文，但本机没有主密钥或主密钥不对 | 仓库内自带 `ocft-backend/master.key`；若本机存在 `~/.ocft/master.key` 会优先使用它，不匹配时删掉或改名 |
| `/api/health/ready` 返回 503，模型状态 `not_configured` | 没有 `ocft-backend/.env` 或 `LLM_API_KEY` 为空 | 复制 `.env.example` 为 `.env`，填 `LLM_API_KEY`（推荐密文） |
| 前端页面能开，提问后一直转圈或报网络错误 | 后端没起来，或 Vite 代理连不上 8000 | 看后端窗口日志；浏览器直接访问 `http://127.0.0.1:8000/api/health/live` 确认后端存活 |
| 新加的表或字段不生效 | 只改了 `app/models.py`，没写迁移：已有表不会自动加列 | 在 `app/migrations.py` 的 `MIGRATIONS` 末尾追加一条（加列用 `add_column_if_missing`），重启后端或执行 `python -m db.seed` |
| 启动报迁移失败 | 某条迁移执行出错，失败的版本不会登记 | 看报错修好迁移函数后重启即可，已成功的版本不会重复执行；`schema_migrations` 表记录了已执行的版本 |

## 二、赛时故障处理

run 失败时，`errorCode` 在前端结果、`/api/agent/runs/{runId}` 和评测输出 `results.jsonl` 里都能看到。

| errorCode / 现象 | 含义 | 处理 |
|------------------|------|------|
| `auth_failed` | Key 无效、过期或欠费 | 换备用 Key（主备各一，密文写入 `.env`），重启后端 |
| `rate_limited` | 模型限流 | 评测是逐题顺序执行的，等一两分钟后用原命令重跑（断点续跑会跳过已完成的题），也可用 `--limit N` 分批；仍不行就换备用 Key |
| `timeout` / `run_timeout` | 单次模型调用或整次 run 超过时限 | 偶发的直接重跑；集中出现时先看是否同一类题在反复调工具，按评测归因交 A 改 Prompt 或工具；不要为了跑通把时限调到很大 |
| `unavailable` | 连不上模型服务 | 检查网络和 `LLM_BASE_URL`；主办方接口和 DeepSeek 公共接口只改 `LLM_BASE_URL` / `LLM_API_MODEL`，不换模型 |
| `bad_request` | 接口拒绝请求，常见是模型 ID 不被接受 | 核对主办方文档里的模型 ID，改 `LLM_API_MODEL` |
| `execution_failed` | 引擎内部异常 | 后端日志搜对应 `runId` 的 `engine_error` 拿堆栈，交 A；不要吞异常、不要返回模板答案（红线 5） |
| `/api/health/ready` 数据库项失败 | MySQL 不可达 | 先确认网络、账号和云数据库白名单是否包含本机出口 IP；短时恢复不了，赛时可切本地 MySQL（改 `config.yaml` 的 database 段后重启，种子会自动导入）；切换后在开发日志记一条 |
| 评测中途中断 | 进程被杀、网络断开等 | 原命令重跑即可（默认断点续跑）；只有确认要整批重来才加 `--fresh` |
| 合规误拦正常问题 | 词库或规则过宽 | 把原句记下交合规负责人：业务术语加 `allowlist.txt`，或收窄规则；不要直接关闭合规检查 |

## 三、处理原则

- 不改运行时模型，不读评测标签，不为了让某道题通过而写死答案。
- 修复后跑 `python -m pytest tests -q` 和红线扫描，再经 A 合入 `main`。
- 故障和处理方式都在[开发日志](../10-strategy/开发日志.md)追加一条，提交测试报告时会用到。
