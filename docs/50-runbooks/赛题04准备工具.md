# 赛题 04 准备工具

状态：生效。范围：离线数据体检、评测输入隔离、结果文件校验。无新增依赖，无数据库写入，无模型调用。

## 1. 数据体检

从仓库根目录进入后端，使用能运行项目依赖的 Python 环境：

```bash
cd ocft-backend
python -m eval.dd04_data --data-dir ../docs/00-rules/赛题/赛题04_企业智能信贷尽调/data --output-dir eval/output/dd04-preparation
```

输出 `data-audit.json` 和 `data-audit.md`。退出码 0 表示无 error；warning 必须人工复核。检查表头、候选键、企业外键、空值、数字/日期类型、连续三年记录、资产勾稽及关系文件结构。报告不复制个人姓名、证件号或财务原值，不修改输入文件；输出目录必须位于原始数据目录之外。

实物为 9 张业务表，不是说明里写的 10 张；另有关系、问询和答案文件。体检仅打开白名单中的 9 张业务表及关系文件。明细表的组合键是重复排查线索，最终数据库主键仍由数据负责人确认。三年检查只看连续性，申请时点应该使用哪三年仍待业务确认；勾稽容差为 0.01 原始金额单位，不是授信阈值。无流动资产、流动负债和营业成本时，不推算流动/速动比率与毛利率。

## 2. 评测输入准备

以下命令仅生成输入 JSONL。`--scenario-id` 必须填写核心负责人实际注册并验证过的赛题 04 场景 ID，**不要把现有 credit_review 当成本题场景**。

```bash
python -m eval.dd04 prepare --input ../docs/00-rules/赛题/赛题04_企业智能信贷尽调/data/loan_application.csv --kind applications --scenario-id <已注册的赛题04场景ID> --output eval/output/dd04-preparation/applications.jsonl
python -m eval.dd04 prepare --input ../docs/00-rules/赛题/赛题04_企业智能信贷尽调/data/question_public.csv --kind questions --scenario-id <已注册的赛题04场景ID> --output eval/output/dd04-preparation/questions.jsonl
```

申请输入只取 `application_id`、`enterprise_id`；问询只取 `question_id`、`enterprise_id`、`question`。输出只含 `id`、`question`、`scenarioId`，企业编号作为上下文写入问题。所有额外列均丢弃，包括 `reference_answer`、`expected` 和结论列。不会读取 `公开测试集答案.csv`，不会把参考答案转换成关键词期望。参考答案评分由评测负责人在评分侧独立接入。

场景实现、数据导入与接口验收后，才运行下面的现有统一入口（会调用模型、产生费用和运行记录）：

```bash
python -m eval.run --input eval/output/dd04-preparation/applications.jsonl --output-dir eval/output/dd04-applications --fresh
python -m eval.run --input eval/output/dd04-preparation/questions.jsonl --output-dir eval/output/dd04-questions --fresh
```

当前通用 runner 还不会生成官方六列业务答案。本轮未实现或声称已跑通该转换，等待结构化结果契约，不能从自由文本猜字段或填充默认评级、额度。

## 3. 官方结果格式校验

```bash
python -m eval.dd04 validate --applications ../docs/00-rules/赛题/赛题04_企业智能信贷尽调/data/loan_application.csv --results <系统实际输出的结果.csv>
```

输出 JSON，失败退出码 1。校验 UTF-8 BOM、精确六列及顺序、输入/输出编号对应、企业编号对应、重复/未知/遗漏申请和空字段。表头如下：

```csv
application_id,enterprise_id,risk_level,suggested_credit_amount,due_diligence_conclusion,scoring_points
```

不验证评级与额度的业务正确性，不以 `scoring_points` 自述作为实际得分。失败任务由 runner 的 `results.jsonl` 保存终态与错误；缺失或空结果会令校验失败，不能为了格式通过而填业务结论。没有成功行的空文件也会失败。
