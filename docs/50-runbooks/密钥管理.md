# 密钥管理

> 数据库连接串、模型 API Key 以密文写在 `.env`，运行时用本机主密钥解密。实现：`ocft-backend/app/secret_box.py`。
> 方案选型与其他备选见 [ADR-0003](../20-architecture/adr/0003-敏感配置加密方案.md)。

## 原理

| 组成 | 存放位置 | 能否入库 |
|------|----------|----------|
| 密文 `enc:gAAAA...` | `ocft-backend/.env` | 可以（拿不到主密钥就解不开） |
| 主密钥 | 环境变量 `OCFT_MASTER_KEY`，或本机文件 `~/.ocft/master.key` | **绝不入库**，不发群里 |
| 明文 | 只在后端进程内存中 | — |

算法：Fernet（AES-128-CBC + HMAC-SHA256）。主密钥不对或密文被篡改时启动直接报错，不会回退成明文。

## 首次配置（团队一人做）

```bash
cd ocft-backend
python -m app.secret_box init        # 生成 ~/.ocft/master.key
python -m app.secret_box encrypt     # 提示输入时粘贴明文（不回显），输出 enc:...
```

把输出的 `enc:...` 填进 `.env`：

```dotenv
LLM_API_KEY=enc:gAAAAA...
DATABASE_URL=enc:gAAAAA...
```

主密钥文件内容通过私聊或密码管理器分发给队友，各自放到 `~/.ocft/master.key`，或设置环境变量 `OCFT_MASTER_KEY`。

## 模型配置

| 变量 | 说明 |
|------|------|
| `LLM_API_KEY` | 模型 Key，推荐 `enc:` 密文 |
| `LLM_BASE_URL` | 默认 `https://api.deepseek.com`；使用主办方接口时改成其地址 |
| `LLM_MODEL` | 产品身份，留空即 `deepseek-v4.1-flash`，写其他值拒绝启动 |
| `LLM_API_MODEL` | 接口实际接收的模型 ID。DeepSeek 公共接口为 `deepseek-flash`（默认）；主办方接口若直接使用 `deepseek-v4.1-flash` 则改成它。白名单外的值（如 `deepseek-v4-pro`、`deepseek-chat`）一律拒绝启动 |

## 比赛期间：克隆即可用（2026-10-22 团队决策）

为保证整个仓库下载即可运行，比赛期间 `ocft-backend/.env`（含模型 Key 与阿里云 MySQL 连接串的密文）和 `ocft-backend/master.key` 随**私有仓库**提交。主密钥查找顺序：环境变量 `OCFT_MASTER_KEY` > `OCFT_MASTER_KEY_FILE` 指定的文件 > `~/.ocft/master.key` > 仓库内 `ocft-backend/master.key`。

赛后由团队删除仓库中的这两个文件、轮换模型 Key 与数据库密码、吊销 GitHub token。仓库不得改为公开。

## 日常使用

- 有主密钥：正常启动，配置加载时自动解密。
- 没有主密钥：启动报错，提示缺少 `OCFT_MASTER_KEY`。
- 数据库统一用 MySQL（2026-10-24 决策），连接配置在 `config.yaml` 的 database 段；SQLite 只用于自动化测试的临时库。

## 换密码 / 换 Key

重新执行 `encrypt` 生成新密文，替换 `.env` 中的值即可。主密钥不用换。

## 边界

- 主密钥泄露等于明文泄露：主密钥和密文不能放在同一个公开位置。
- 评委机器上没有主密钥：交付时要么附上 Key 密文 + 主密钥（通过安全渠道），要么在 README 写明让评委自行填写 `LLM_API_KEY`。
