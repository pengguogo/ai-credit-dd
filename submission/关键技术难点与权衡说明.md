# 关键技术难点与权衡说明

> 《通用提交材料说明》可选材料。当前方案以赛题04实现、Agent API 契约和 ADR-0004/0008 为准；最终数字只引用同一冻结 SHA 的实测结果。

## 1. 结论可追溯，但运行时不能读取答案

- **难点**：评测要求评级、额度、结论和要点正确，同时红线禁止在 Prompt、工具、种子或前端预存答案，也禁止运行时读取 `expected` 和外部汇总评级。
- **做法**：九类业务事实进入只读工具和确定性计算；评分卡、额度、欺诈规则在运行时按输入重算。每个结论绑定 evidence 快照、来源、主键和内容哈希；公开答案只在 `eval/` 离线对照。
- **代价**：公开集参数校准不等于泛化证明，必须披露配置依据，并用现场新企业验证；不能用题号特化补正确率。

## 2. 主控加六角色，而不是界面标签

- **难点**：赛题需要多 Agent 协作，但简单把一份回答拆成六个名称不构成真实协作。
- **做法**：主控负责对象定位和调度；工商、财务、舆情先生成结构化事实，反欺诈依赖上游结果，评级授信依赖反欺诈，报告最后汇总。角色有独立 Prompt、运行时 Skill、输入输出契约、调用记录和 SSE 事件。
- **取舍**：LangGraph 负责调度，模型仍只经 `app/llm.py`，工具只经注册表；不使用框架 ChatModel/checkpointer，证据和终态仍由自研代码控制。
- **代价**：多角色提高 token、时延和失败点；角色降级时保留确定性数字但进入人工复核，不生成假解读。

## 3. 确定性计算与模型表述分离

- **难点**：LLM擅长理解和成文，但不适合承担金融数值计算。
- **做法**：财务指标、风险规则、评级和额度由 Python/Decimal 与 YAML 配置计算；模型只解释结构化结果。报告中的数字、评级、规则编号和证据编号在发布前与本次工具结果核对。
- **局限**：当前事实校验不覆盖所有趋势、因果和业务语义；通过校验不等于整篇报告业务正确，仍需人工复核。

## 4. 有界执行与诚实失败

- **难点**：六角色完整尽调可能超过早期 6轮/60秒限制，模型也可能超时、截断或产生无法验证的叙述。
- **做法**：当前默认不限制 run 总工具轮数和总墙钟；保留单次模型调用超时、角色输出 token、重试和 run 累计 token 上限。赛题04累计上限为200,000，普通调用默认30秒，报告角色60秒。
- **终态**：成功、待确认、待澄清、证据不足、拦截和失败分别展示；事实校验重写仍失败时返回 `narrative_check_failed`，已计算结构可留作证据，但不发布有疑点正文。
- **代价**：不承诺固定秒数完成；现场演示需要网络与模型状态预检。

## 5. 全链路脱敏与本地可用性的平衡

- **难点**：模型需要理解企业关系，但企业、人名、信用代码和地址不能原文外送或无控制发布。
- **做法**：本次 run 建立实体到代号的映射，模型只看到代号；工具参数仅在本地执行前还原。最终只恢复企业/机构名称，自然人保留代号，号码继续掩码。模型调用记录保存脱敏预览与请求哈希。
- **图片取舍**：没有本地图像脱敏能力，因此非空附件在创建 run 前统一422；不以“图片不落库”替代外送合规。
- **局限**：未知实体和自由文本仍可能超出规则覆盖，最终截图、日志、报告和导出必须人工抽查。

## 6. 统一持久化、证据与审计

- **难点**：run、工具、证据、确认、记忆和事件需要可恢复且权限一致。
- **做法**：业务事实与执行记录统一使用 MySQL；执行中的 SSE 由单进程内存 EventBus 推送，run 结束后由 MySQL `run_events` 重放。Redis 当前只作为 readiness 强依赖做连通检查，不宣称已承载业务缓存、计数或锁。写操作与审计同事务，审计只追加；确认绑定身份、runId 和答案版本并支持幂等。
- **代价**：当前交付运行时依赖云 MySQL/Redis，不是完全离线业务系统；README 和 manifest 必须声明网络及白名单。

## 7. 离线安装与远程运行服务

- **难点**：评委机不能临时联网下载依赖，但模型和当前云数据服务又必须联网访问。
- **做法**：系统包内置 Windows Python、固定版本 wheels 和前端 dist；`start.bat/start.ps1` 使用 `--no-index` 安装。离线只指依赖安装与页面启动，模型 API、云 MySQL/Redis 仍需网络。
- **验证边界**：本机空目录预演已通过；另一台干净 Windows 真断网安装、双击启动及评委机出口白名单仍待完成，不能把本机预演写成目标机验收。

## 8. 现场新数据与交付一致性

- **难点**：官方非公开集赛前不提供结果，现场输入格式可能变化。
- **做法**：使用 `app.dd_import → eval.dd04 prepare → eval.run → eval.dd04 export → eval.dd04 validate` 同一链路；优先调整配置和字段映射，不改公共引擎。失败与待确认行照实保留。
- **边界**：PDF输入当前不支持，需先转换为结构一致的CSV/XLSX并人工核对；A4团队衍生5笔只证明流程，不是官方非公开成绩。

## 9. 当前未闭环事项

- 公开基线仍有2笔 `narrative_check_failed`，高风险样本一致性未完全稳定。
- 浏览器七项功能、异机离线安装、正式截图/视频/报告样例、技术与测试PDF、manifest和元信息仍需最终验收。
- 最终提交必须在同一冻结 SHA 上重跑测试、lint/build、红线扫描、公开/现场结果和脱敏复核。
