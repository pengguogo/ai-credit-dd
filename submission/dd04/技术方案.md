## 1. 多 Agent 架构

### 1.1 总体形态：主控 + 六个业务角色 + 确定性工具（ADR-0008）

系统采用「统一主控 + 六个业务角色 + 确定性计算工具」的多 Agent 架构：

- **主控（controller）**：沿用场景工具循环，负责意图识别、对象定位（企业 / 申请）、歧义澄清、决定是否发起尽调子计划。不设轮数上限，由 token 预算兜底（`agents.yaml` 的 `controller.max_total_tokens`）。
- **六个业务角色**：工商核验（business）、财报解析（finance）、舆情扫描（opinion）、反欺诈（fraud）、评级授信（rating）、报告（report）。每个角色有独立职责、结构化输入输出（Pydantic 校验）和真实执行记录（`llm_calls.purpose=role:*`）。
- **确定性工具（`app/tools/dd_calc.py`）**：所有业务数字（指标、评分、评级、额度）由纯函数实时计算，模型只做解读与成文，不改数值。

候选方案比较：开放式自治 Agent 对话轮次与冲突不可控，难以满足 30 秒级时延与同输入稳定复现，未采用；单主 Agent 直调工具不满足本题多 Agent 协作要求，保留为其他场景的运行方式。

### 1.2 执行流程（完整尽调）

```text
用户请求 → run_service（输入合规 + PII 掩码）
        → 主控工具循环（意图 / 定位 / run_dd_agents）
   run_dd_agents(mode=full)
        → prepare：只读快照 + 代号化（主线程，冻结十张表）
        → compute：按依赖顺序算完全部数字（纯函数，毫秒级）
        → business / finance / opinion / fraud / rating 并行解读（各一次模型调用）
        → report：报告角色成文
        → verify：事实校验（纯函数）
        → engine 判定终态 → 输出合规（还原企业名称）→ 证据与轨迹落库
```

- **prepare 快照**：读出申请与十张表，深拷贝冻结；角色只读快照，数据库访问只在主线程的读（prepare）与写（收尾落库）两个阶段，并行角色不持有 Session，规避 ORM 并发问题。
- **并行解读口径**（`agents.yaml` 的 `parallel_analysis: true`，默认开启）：`compute` 先把五个角色的数字全部算完，五个解读同时调用模型（按各角色 `max_tokens` 预占 token）；反欺诈、评级的解读只看上游数字，不看上游文字判断。设为 `false` 回到逐级串行（business/finance/opinion 并行 → fraud → rating → report）。该改造使公开集单笔耗时从平均约 81 秒降至 22–26 秒。
- **静态拓扑 + 跳过**：六个角色节点始终在 LangGraph 图中，不在计划内的角色进入后直接返回 `skipped`，事件可预测；未采用动态 `Send`。
- **调度边界**：只用 LangGraph 做依赖调度；模型只经 `app/llm.py` 调用锁定的 `deepseek-v4.1-flash`，不用框架自带 ChatModel / ToolNode。

### 1.3 角色执行模板

每个角色统一三步（`app/agent/dd_roles.py`）：

1. **计算**：调用 `dd_calc` 纯函数（`verify_business` / `analyze_financials` / `scan_public_opinion` / `detect_fraud` / `rate_risk` + `calc_credit_limit` / `build_report`）。
2. **分析**（角色配置 `llm: true` 时）：把代号化的计算摘要送给模型，temperature=0，输出 JSON `{analysis, keyFindings[], uncertainties[], needsReview}`，Pydantic 校验失败回错重试 1 次，仍失败记为 `degraded`。
3. **产出** `RoleResult`：role、status（`ok`/`degraded`/`skipped`/`failed`）、data、analysis、待落库证据、调用审计、usage、durationMs。计算抛 `ToolError`（如企业不存在）时该角色 `failed`，下游依次 `skipped`，系统如实终态失败，不回填模板结论。

### 1.4 角色配置与路径

| 配置项 | 路径（`ocft-backend/scenarios/dd04/`） | 用途 |
|---|---|---|
| 角色编排 | `agents.yaml` | 角色开关、依赖（depends_on）、每角色 max_tokens / timeout、主控 token 上限、thinking 开关、parallel_analysis |
| 角色提示词 | `prompts/*.md` | 六个角色的分析要求与输出契约说明 |
| 场景注册 | `app/agent/scenarios.py` | `Scenario(system_prompt, allowed_tools)`，换场景只换场景包 |

ADR-0008 五项关键拍板：① 运行时不读外部汇总评级 `risk_level_summary`；② 六角色默认全开模型分析（可按角色配置关闭）；③ 首版无角色补查（预取完整快照，见 11.4 已知局限）；④ 不限轮数不限总时长，保留 token 上限与单次调用超时兜底；⑤ 名称与隐私规则——持久化问题隐藏库内已知自然人、企业名称可保留，外送模型使用 run 内代号，发布时仅还原企业/机构名称，自然人和号码保持代号或掩码。

## 2. 数据导入与建模

### 2.1 原始数据与表建模

原始数据包为 9 张业务表 CSV + 1 张关系说明（`schema_relationships.csv`），另有单独的问询自测集（`question_public.csv`）与公开测试集答案文件（不进入运行时，见 11.3）。表结构与模型/工具映射：

| 原始 CSV | 业务键 | ORM 模型（`app/models.py`） | 消费工具 |
|---|---|---|---|
| enterprise_basic.csv | enterprise_id | EnterpriseBasic | verify_business |
| enterprise_finance.csv | enterprise_id + year | EnterpriseFinance | analyze_financials |
| enterprise_shareholder.csv | enterprise_id + 股东名 + 类型 | EnterpriseShareholder | verify_business |
| enterprise_lawsuit.csv | case_id | EnterpriseLawsuit | scan_public_opinion |
| enterprise_public_opinion.csv | event_id | EnterprisePublicOpinion | scan_public_opinion |
| enterprise_related.csv | enterprise_id + 关联名 + 类型 | EnterpriseRelated | verify_business / detect_fraud |
| enterprise_guarantee.csv | enterprise_id + 被担保方 + 类型 + 期限 | EnterpriseGuarantee | verify_business / detect_fraud |
| enterprise_risk.csv | enterprise_id | EnterpriseRisk | 评分卡（不读 risk_level_summary） |
| loan_application.csv | application_id | LoanApplication | run_service 定位 / 额度测算 |

建模约定：金额单位统一万元、Decimal 运算；迁移只追加（`app/migrations.py`）；原始事实与推导结果分表存储，推导结果（证据快照）不覆盖原始行。

### 2.2 三条导入路径（同一套校验与模型）

1. **默认样例（启动自动灌入）**：`db.seed` 在后端启动时幂等导入 `scenarios/dd04/data/` 下的样例数据，重复启动不产生重复行。
2. **整批换数据**：`python -m app.dd_import <目录>` 覆盖式导入官方数据包；**自动跳过 `question_public.csv` 与公开测试集答案文件**，保证参考答案不进入运行时库。
3. **增量新增**：工作台业务数据页各表的「导入」按钮（按表弹窗），或 `POST /api/agent/data/imports`（1–9 个业务 CSV，单文件 ≤10MiB、≤20000 条；同键同内容跳过、同键不同内容返回 409 拒绝，不静默覆盖；`schema_relationships.csv` 不接受导入）。

导入均走字段白名单与类型校验，失败行携带定位信息返回，不整批静默吞错。

### 2.3 答案列隔离（T0 改造）

`enterprise_risk` 表的 `risk_level_summary`（外部汇总评级）列在数据库中保留（导入需与原 CSV 一致），但运行时任何代码不读取：工具、证据、目录、提示词、`sql_query` 白名单全部覆盖，`tests/test_dd_answer_isolation.py` 回归保护。

## 3. 财报解析

### 3.1 期间与勾稽口径

- **取数期间**：申请日之前最近的完整年度为基准年，同时保留近三年科目做趋势；缺少披露日期字段，报告如实注明「不能保证申请当日已经披露」。
- **勾稽校验**：资产 = 负债 + 所有者权益，容差 1 万元（`metrics.yaml` 的 `balance_tolerance`），超差记为异常线索并关联证据。
- **金额单位**：万元；展示舍入最后执行，不用显示值参与下游计算。

### 3.2 指标清单（`scenarios/dd04/metrics.yaml`，改阈值只改配置）

| 指标 | 口径 | 警戒线（warn） | 拦截线（block） |
|---|---|---|---|
| 资产负债率 | 总负债/总资产 | > 0.70 | > 0.85 |
| 净利率 | 净利润/营业收入 | < 0.03 | < 0 |
| 净资产收益率 ROE | 净利润/所有者权益 | < 0.05 | — |
| 总资产收益率 ROA | 净利润/总资产 | < 0.02 | — |
| 经营现金流/净利润 | — | < 0.5 | — |
| 应收账款周转天数 | 平均应收×360/营业收入 | > 120 | — |
| 存货周转天数 | 平均存货×360/营业收入 | > 180 | — |
| 有息负债/总资产 | — | > 0.40 | > 0.60 |
| 期间费用率 | 三费合计/营业收入 | > 0.25 | — |
| 研发费用率 | 研发费用/营业收入 | < 0 | — |

- **分母口径**：数据集没有营业成本，存货与应收周转以**营业收入**为分母（`turnover_denominator: revenue`，报告中显式说明该口径）。
- **缺失指标不编造**：数据集没有流动资产、流动负债、营业成本，**流动比率、速动比率、毛利率不计算**，报告注明不可得，不填默认值。
- 零值与负值：净资产等口径在额度测算中按 `max(x, 0)` 截断（公式见第 7 章）；指标计算保留原始负值并触发对应警戒线。

每个指标的计算输入（科目、年度）、公式、结果与命中情况写入证据行，可从报告数字回溯到原始财报行。

## 4. 工商核验

### 4.1 核验项与方法

| 核验项 | 方法 | 阈值 / 口径（`scorecard.yaml`） |
|---|---|---|
| 基础信息一致性 | 申请信息与企业基础表逐项对照（行业、成立时间、经营状态） | 经营状态正常值：在业（`normal_status`） |
| 资本实缴 | 实缴资本 / 注册资本 | < 0.80 记异常线索（`paid_in_min_ratio`） |
| 股东与控制 | 股东名册按类型汇总，识别法人/自然人持股结构 | 仅陈述事实，不穿透到无法核验的层级 |
| 关联企业 | 关联表按企业聚合，按关系类型分组 | ≥ 4 家且存在担保圈时进入反欺诈 F06 线索 |
| 对外担保 | 担保表逐笔列出（被担保方、类型、期限、金额） | 担保/净资产 ≥10% 记 1 点、≥30% 记 2 点（进评分卡） |
| 经营异常/失信/限高 | 风险表字段 | 一票否决项（见第 7 章 veto） |

### 4.2 边界

不凭「法人与实控人姓名不同」认定欺诈（同名/代理是正常商业事实）；未穿透核验的关联关系如实标注为事实陈述而非控制结论。每项核验结论关联来源表行主键，作为证据落库。

## 5. 舆情扫描

### 5.1 打分模型（`scenarios/dd04/opinion.yaml`）

舆情与涉诉合并为舆情风险分 `opinionRiskScore`（0–100，越高风险越大），健康分 = 100 − 风险分：

- 基础分 20；舆情事件按「情感 × 影响等级 × 时间衰减」计分：情感 正面 −6 / 中性 +2 / 负面 +14，影响 低 1.0 / 中 1.6 / 高 2.4，按事件日期每年衰减 0.85（截止时点 = 申请日 `as_of`）。
- 涉诉按案件状态 × 诉讼角色分桶计分：未结被告 18 / 未结其他角色 6 / 已结被告 4 / 已结其他 1；未结被告案件金额单独累计为 `openDefendantAmount`，进入评分卡的「涉诉金额/净资产」指标。
- 事件标签：司法执行、行政处罚、经营负面、荣誉资质（关键词命中）+「未结被告/被执行」（分桶判定）。

### 5.2 口径与边界

- **时间口径**：所有事件按申请日截止，早于申请日的按年衰减，晚于申请日的不计入（数据集均为历史事件）。
- **空记录处理**：无舆情无涉诉时得基础分 20，健康分 80，不报错、不视为缺失。
- **汇总评级对照**：评分卡的 `public_opinion_score` 指标优先使用原始输入字段（事实特征），缺失时退回本系统计算的健康分；外部汇总评级不参与任何计分（红线 R5）。
- **去重**：事件按 event_id、案件按 case_id 天然去重（表业务键），同一事件多来源不重复计分。

每条事件的计分明细（情感、影响、衰减、得分）保留在结构化结果与证据中，可逐条复核。

## 6. 反欺诈检测

### 6.1 规则清单（`scenarios/dd04/fraud_rules.yaml`，F01–F06）

命中与否由工具按当年数据实时计算，不读取任何预存结论：

| 规则 | 名称 | 判定公式（阈值） | 置信度口径 |
|---|---|---|---|
| F01 | 营收与经营现金流背离 | 经营现金流 / 营业收入 < 0.02 | 实际值偏离阈值 ≥ 50% 记 high，否则 medium |
| F02 | 存货异常增长 | 存货增速 ≥ 20% 且高出营收增速 ≥ 30 个百分点 | 同上 |
| F03 | 应收增速高于营收增速 | 应收增速 − 营收增速 ≥ 10 个百分点 | 同上 |
| F04 | 其他应收款占比偏高 | 其他应收款 / 总资产 ≥ 0.08 | 同上 |
| F05 | 净利与现金流长期背离 | 连续 ≥ 2 年经营现金流 / 净利润 < 0.30 | 同上 |
| F06 | 关联企业多且存在担保圈 | 关联企业 ≥ 4 家 且 存在对外担保 | 离散命中记 high |

命中输出包含：实际值、阈值、覆盖期间、置信度、关联数据行（证据）、建议补件材料（如核查关联交易明细、资金流水）。

### 6.2 定位与边界

- 反欺诈命中是**待核实线索，不是结论**：不进入评分卡一票否决，而是通过「重大财务异常折减」承接（见 7.2），避免把线索写成定论。
- 数据集无交易流水，**交易占比、资金往来真实性明确标注「不能核实」**并列入建议核查项，不编造比例。
- 规则编号、公式、阈值全部外置配置，新增规则不改代码（登记到 yaml + 单测）。

## 7. 额度测算模型

### 7.1 风险评级（点数制评分卡 `score-points-v2`）

九项连续指标 + 两项标志项，每项 0–3 点（越高越差），合计点数自上而下取第一个满足 `total ≤ max_points` 的档位：

| 指标 | 1 点 | 2 点 | 3 点 |
|---|---|---|---|
| 资产负债率 | ≥45% | ≥60% | ≥70% |
| 净利率 | <10% | <6% | <3% |
| 经营现金流/净利润 | <1.0 | <0.5 | <0（为负） |
| 应收账款/营业收入 | ≥15% | ≥30% | ≥40% |
| 逾期次数 | — | — | 有逾期即 3 点 |
| 涉诉金额/净资产 | ≥5% | ≥15% | — |
| 对外担保/净资产 | ≥10% | ≥30% | — |
| 舆情评分 | <80 | <65 | <50 |
| 法定代表人失信/限高 | 标志命中 2 点 | | |
| 对外担保逾期 | 标志命中 2 点 | | |

档位映射：≤1 点低风险；≤4 点低-中风险；≤19 点中风险；其余高风险。

**一票否决（命中即高风险、额度为 0）**：法定代表人失信/限高、高消费限制、未结清逾期。反欺诈命中**不否决**，由 7.2 的异常折减承接。

### 7.2 额度测算（模拟政策 `incremental-v2`，团队模拟政策，非银行审批制度）

额度工具内部仍以申请金额作为测算硬上限；`f9594d9` 之后，申请额仅留在确定性计算和“是否可通过”类追问的本地对照中，不进入尽调报告正文、报告角色输入或报告事实校验源。

```text
财务能力   C = min( max(营业收入, 0) × 0.12 , max(所有者权益, 0) × 0.40 )   （万元）
评级调整   R = C × 评级系数（低/低-中/中 = 1.0；高风险 = 0）
硬上限     H = 0（高风险或一票否决时）；否则 min(申请金额, R)
建议区间   正常：H × [0.85, 1.0]
           命中 ≥2 项重大财务异常：H × [0.6, 0.8]（审慎压降）
取整       H ≥ 2000 万元：下界/上界向下取整到 500 万元一档；否则 100 万元一档
输出       下界=上界时输出单值，否则输出「下界-上界」区间
```

报告仅展示建议授信额度；传给报告角色及报告结构的 `steps` 会过滤“申请额封顶”步骤，避免反向披露本次申请额。

**重大财务异常（A1–A4，需 ≥2 项才触发折减）**：

| 编号 | 异常 | 判定 |
|---|---|---|
| A1 | 营收与现金流背离 | 经营现金流 ≤ 0，或 < 净利润 × 0.5 |
| A2 | 应收占比过高 | 应收账款 / 营业收入 ≥ 40% |
| A3 | 其他应收款占比过高 | 其他应收款 / 总资产 ≥ 10% |
| A4 | 担保圈 | 对外担保的关联企业 ≥ 2 家 |

利率方向按档位给（低风险下浮 / 低-中持平 / 中风险上浮 / 高风险不适用）；期限与担保方式沿用申请值。额度工具保留完整内部 `steps`（营收口径上限 → 净资产口径上限 → 取小 → 评级调整 → 申请额封顶 → 异常折减 → 区间取整），但 `f9594d9` 后报告角色输入与报告结构会过滤“申请额封顶”，正文只呈现不含申请额的测算依据。风控条件条款按实际命中项生成：存量贷款与对外担保核验、异常线索投放前核查、经营现金流非正核验还本付息来源、否决项未解除不新增授信、逾期结清前不投放等。

契约与错误码见 [contracts/dd04-credit-amount.md](../../contracts/dd04-credit-amount.md)；单位不一致等输入错误抛 `ToolError`，不静默换算。

### 7.3 阈值来源与公开集校准披露

**如实披露**：评分卡档位边界（如负债率 45/60/70%、净利率 10/6/3%）、额度系数（0.12 / 0.40）、折减区间（0.6–0.8）与取整档位，是有信贷业务含义的整档设定，并**经官方公开测评集（10 笔）校准过边界**（公开题拟合策略）。运行时只从原始事实重算，不读取任何答案列；非公开集上存在边界抖动风险（数值落在档位边界附近时结论可能翻转），该风险在测试报告中量化披露。

### 7.4 已知局限（如实披露）

- 期限照搬申请值，未按政策反推合理期限；
- 利率只给方向（下浮/持平/上浮），无基准利率与点差，不伪造市场报价；
- 贷款用途对额度的影响很小（用途仅进入建议与核查项，不进公式）；
- 关联交易缺金额字段，算不出关联交易占比，列为「不能核实」。

## 8. 尽调报告生成

### 8.1 报告结构（五部分，`build_report` 确定性组装）

| 章节 | 内容来源 |
|---|---|
| 企业概况 | 基础表（行业、经营状态、成立时间）+ 工商核验 findings |
| 财务分析 | 指标表（含口径说明：单位、周转分母、不可得指标）+ 近三年增长 |
| 风险提示 | 评级与得分、一票否决项、反欺诈命中规则、舆情标签、是否需人工复核 |
| 额度建议 | 建议额度（单值/区间）、期限、利率方向、担保方式、已过滤申请额封顶的测算依据、政策版本、敞口与假设 |
| 风控条件 | 按实际命中项生成的条件性条款（不命中不生成，不写空话） |

结构化结果是唯一事实源：界面、导出、问答都从同一结果读取，不分别再调模型生成评级额度。

### 8.2 成文与事实校验

- 报告角色把结构化结果组织为成文报告（temperature=0，角色级 60 秒超时、专属 max_tokens）；模型输出仍以结构化字段为骨架。
- **事实校验器（`dd_verify.py`，纯函数）**逐项核对：带单位数字（允许舍入、保留正负号）、风险档位、规则编号、本次 `ev_` 证据引用。校验不通过且可重试则回到报告角色重写；仍不通过则终态 `failed`，错误码 `narrative_check_failed`，**不发布模板假报告**。免责声明「测算建议，非授信审批」由确定性代码补为普通段落，不作为拦截项。
- 报告引用的每个 `ev_` 证据号对应 `evidence` 表真实行（来源表、主键、计算输入、结果快照、内容哈希）。

### 8.3 预览与导出

- 报告预览页 `/report-preview.html?runId=…` 展示五部分 + 证据抽屉；PDF 用本机浏览器「另存为 PDF」完成（交互式打印流程，**不宣称服务端自动 PDF 导出**）。
- 官方六列结果（application_id、enterprise_id、risk_level、suggested_credit_amount、due_diligence_conclusion、scoring_points）由 `eval/dd04.py export` 从结构化结果导出，UTF-8-SIG，`validate` 子命令校验列名与顺序；`scoring_points` 只写本笔实际事实与规则命中，不从任何标签复制。

## 9. 自然语言问询

### 9.1 链路（与完整尽调同一 run 服务）

问询走 `POST /api/agent/runs` 同一入口与会话，不另建问答系统：

- **意图路由**：主控按问题选择直接工具回答（`get_loan_application` / `find_enterprise` / `sql_query`，后者受字段白名单约束）或发起 `run_dd_agents(mode=followup)`。
- **followup 子计划**：只执行该问题所需的角色依赖闭包（问「资产负债率」只跑 finance；问「额度为什么压降」跑 finance → rating → credit），依赖闭包按 `agents.yaml` 的 `depends_on` 递归补齐；若现有结果不适用则现场重算，不为省调用复用失效结论。
- **歧义与缺失对象澄清**：多企业同名时，或问题没有申请编号、企业编号、企业名称且会话也没有可指代对象时，第一步调用 `request_clarification` → 终态 `needs_clarification`；不以普通回答代替澄清，不猜对象，也不列出库内企业、申请或金额供用户选择（`d70ba07`）。
- **回答溯源**：答案必须携带证据引用，`answersWithoutEvidence` 由运行统计核验（公开集问询 10/10 全部带证据）。

### 9.2 依据与结果

- 问询输入经字段白名单与输入合规检查；**参考答案（question_public.csv 的要点、公开测试集答案）不传入 Agent**，整批导入路径自动跳过答案文件。
- 官方问询自测集 10 题经同一链路实测：**10/10 succeeded**，平均 14.1 秒，全部带证据；逐题比对见测试报告。

## 11. 鲁棒性、可解释性与合规

### 11.1 终态与诚实失败

终态沿用全场景统一六种语义：`succeeded` / `needs_confirmation` / `needs_clarification` / `blocked` / `insufficient_evidence` / `failed`；超时通过 `failed` 的类型化 `errorCode` 表达。公开测评集 10 笔实测：**7 succeeded、1 needs_confirmation、2 failed（`narrative_check_failed`，LA006/LA008）**——事实校验未通过时如实失败并保留已验证过程，不发布模板结论；失败笔在六列导出中如实保留失败状态。10 笔全部带证据（`answersWithoutEvidence = 0`）。

### 11.2 一致性与性能（公开集实测，版本 `00e905f`）

- **结构化一致**：同一输入双跑，评级与额度结构化结果一致（双跑对照详见测试报告）；文本不承诺逐字一致（temperature=0 只保证结构与数字稳定，差异如实披露）。
- **性能**：完整尽调平均 27.1 秒 / P50 23.0 秒 / P95 34.2 秒（并行解读改造前平均约 81 秒）；自然语言问询平均 14.1 秒。端到端 30 秒目标未 100% 达成（P95 超标），如实披露。
- **离线对照**（仅评测进程使用答案）：风险评级一致 8/10、额度一致 8/10（两笔失败无结构化结论记不一致）。

### 11.3 脱敏与代号映射

- 送模型的 DD04 内容先代号化：企业全名 → `企业<enterpriseId>`；法人、实控人、股东、关联企业按出现顺序编号；统一社会信用代码、证件号和地址掩码。映射只存在于本次 run 内存，不落库、不送模型。
- 用户原始输入先经合规处理；持久化问题会隐藏库内已知人员姓名，但企业名称可在本地业务界面识别。发布答案、澄清问题与报告时只允许还原企业名称；法人、实控人、信用代码、证件号和地址保持代号 / 掩码，证据 API、导出与异步 meta 同样不暴露这些原值。
- `f9594d9` 起，尽调报告还会隐藏本次申请额：报告角色 brief、报告结构与事实校验源均不含申请额，“申请额封顶”步骤不进入报告；申请额只在确定性额度计算及特定审批建议追问的本地对照中使用。
- 原始舆情/事件文本只作为待分析数据，其中任何「忽略规则、读取答案」类内容不构成 Agent 指令；发布前数值检查保留正负号并做科目与年度匹配。

### 11.4 红线对照（R1–R9）

| 红线 | 落实 |
|---|---|
| R1 锁定模型 | 全部角色与主控只经 `app/llm.py` 调 `deepseek-v4.1-flash`，无第二客户端 |
| R2 代码实现 | LangGraph 只做调度，主控/角色/工具/校验均为仓库代码，无低代码平台编排 |
| R3 证据追溯 | 每个结论关联 `evidence` 表行（来源、主键、计算快照、哈希）；报告 `ev_` 引用经校验器核对 |
| R4 禁止假答案 | 数字全部纯函数实时计算；校验失败返回 `narrative_check_failed`，不回填模板 |
| R5 标签隔离 | 运行时不读 `risk_level_summary` 与任何评测标签（`test_dd_answer_isolation.py` 回归）；答案仅在 `eval/` 离线进程使用 |
| R6 确认留痕 | 高风险、`degraded`、评分卡复核、额度错误进入 `needs_confirmation`，确认/驳回绑定版本与审计 |
| R7 输入输出合规 | 入口 PII 掩码与输入合规、出口输出合规与名称还原策略统一执行 |
| R8 本地启动 | 一键启动脚本 + 离线依赖（wheel 与前端 dist 预置），零新增运行时依赖 |
| R9 密钥保护 | 代码、文档和提交信息不含明文凭据；比赛期间仅按团队决策在私有交付包中提供 `.env`、`config.yaml` 的密文配置与 `master.key`，赛后删除并轮换全部凭据 |

### 11.5 已知局限（汇总，如实披露）

1. **事实校验范围**：目前只核对数字符号、科目与年度匹配，趋势与因果性描述不校验（B3）。
2. **无角色补查**：预取完整快照，非公开集若出现快照覆盖不到的数据则答不出（重访条件：评测归因显示真实缺失）。
3. **文本不逐字一致**、**P95 超 30 秒**、**额度测算四项局限**（见 7.4）、**公开集校准的边界抖动**（见 7.3）。
4. **进程崩溃不续跑**：未提交事务回滚后允许重新运行，不宣称断点续跑能力。
