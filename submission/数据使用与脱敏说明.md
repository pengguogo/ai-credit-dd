# 数据使用与脱敏说明

> 《通用提交材料说明》可选材料。本文描述赛题04当前实现；最终提交前须用正式截图、报告和输出目录重新执行脱敏复核。

## 1. 数据来源与隔离

| 数据 | 位置 | 运行时边界 |
|------|------|------------|
| 赛题04模拟业务事实 | `ocft-backend/scenarios/dd04/data/` 及数据库九类业务表 | 只作为工商、财务、舆情、诉讼、关联、担保、风险和贷款申请事实；结论运行时重算 |
| 官方公开问询与答案 | `docs/00-rules/赛题/赛题04_企业智能信贷尽调/data/` | 问询可转为运行输入；参考答案只供 `eval/` 离线评分，不进入 Agent 请求、Prompt、工具或业务库 |
| 通用回归标签 | `ocft-backend/eval/fixtures/` | 只由评分器读取，运行时不可见 |
| A4衍生样本 | 评测归档与 `系统输出/非公开测评集结果-演练衍生.csv` | 仅验证现场流程，不称为官方非公开集 |
| 现场官方非公开输入 | 尚未提供 | 到场后仅导入输入，使用同一 pipeline 实时重算，不建立题号到答案映射 |

数据均为官方模拟数据或团队衍生数据，不使用真实客户或企业数据；manifest 中 `real_data_used` 应为 `false`。

## 2. 外部调用

唯一运行时模型是 `deepseek-v4.1-flash`，只经 `ocft-backend/app/llm.py` 调用。模型请求可能包含：

- 场景系统提示、对应角色的版本化 Skill；
- 经输入合规和 PII/名称处理后的用户问题与会话历史；
- 经代号化和掩码处理的工具结果摘要；
- 事实校验重写时的问题清单。

数据库连接串、API Key 和主密钥不会放入模型消息。运行时另需连接云 MySQL/Redis，但二者不属于模型外送；网络依赖在 README 和 manifest 中如实声明。

当前不支持图片输入：任何非空 `attachments` 在创建 run 和调用模型前同步返回 422，不外送 URL、base64 或图像像素。

## 3. 脱敏与代号化

| 环节 | 当前做法 | 主要实现 |
|------|----------|----------|
| 用户输入与会话 | 身份证、银行卡、手机号、邮箱按规则掩码；库内已知自然人替换为 run 内代号；企业名称可在本地业务文本中保留 | `app/compliance/pii.py`、`app/services/run_service.py`、`app/agent/dd_snapshot.py` |
| 模型请求 | 企业、法人、实控人、自然人股东、关联方等先映射为本次 run 代号；号码类 PII 另行掩码 | `app/agent/dd_snapshot.py`、`app/agent/dd_roles.py` |
| 本地工具参数 | 模型返回的登记代号只在本地执行前还原，工具查询仍走参数校验和白名单 | `app/agent/dd_snapshot.py`、工具注册表 |
| 最终回答与澄清 | 输出合规前只还原企业/机构名称；自然人保持代号，信用代码、证件号和地址不还原 | `app/agent/engine.py`、`app/compliance/pii.py` |
| 证据、目录和导出 | 使用独立字段掩码规则；法人、实控人、账号和号码等不以原值发布 | `app/services/run_service.py`、目录与评测导出模块 |
| 模型审计 | 记录用途、时间、模型、usage、请求哈希和脱敏截断预览，不保存 Key | `llm_calls`、`GET /api/agent/runs/{runId}/llm-calls` |
| 应用日志 | 只记录 requestId、runId、终态、耗时和计数等结构化信息，不记录完整问题和答案 | `app/observability/` |
| 敏感配置 | `.env` 和 `config.yaml` 使用 `enc:` 密文，由 `master.key` 解密；比赛期间私有交付包例外见 AGENTS 红线6 | `app/secret_box.py`、ADR-0003 |

A7 复核在模型请求外层截获完整 messages/tools，3个真实 run 共22次模型调用对121个敏感原值命中0；同时扫描 `00e905f` 归档36个导出文件命中0。该记录只证明对应版本和样本，不代替最终产物复扫。

## 4. 留存与提交

| 数据 | 存放与处置 |
|------|------------|
| 会话、run、工具轨迹、证据、确认和审计 | MySQL；证据与审计按设计追加，用 runId 追溯 |
| SSE实时事件 | 执行中由单进程内存 EventBus 推送；run 结束后从 MySQL `run_events` 重放。Redis 当前只做 readiness 连通检查，不承载事件或业务状态 |
| 本地评测临时输出 | `ocft-backend/eval/output/`，默认不提交 |
| 正式系统输出 | `系统输出/`；失败和待确认按真实状态保留 |
| 旧评审与测试证据 | `docs/90-archive/`；保留开发追溯，通过 `export-ignore` 排除评委系统包 |
| 凭据 | 比赛期间按团队决策随私有包提供；限制分发，赛后删除并全部轮换 |

## 5. 已知局限与最终检查

- 规则和已知实体映射不能识别所有未知自然语言实体，仍需人工抽查。
- 事实校验主要覆盖数字、科目、符号、明确年度、评级和规则编号；趋势、因果不等于自动验证完成。
- 新增现场字段或新的自由文本列时，需重新确认字段白名单和脱敏策略。
- 正式截图、视频帧、报告 PDF/Word、CSV、JSON、日志和模型请求必须在最终 SHA 上再次扫描；不能复用旧版本“零命中”替代最终验收。
