# 赛题04 推导测试集：200 家新企业 + 200 笔申请

模拟现场非公开集（未见企业、只给输入），用于测泛化能力。由 [generate.py](generate.py) 以固定种子（`--seed 20261024`）从官方数据包推导，重跑结果逐字节一致。

## 推导方法

- 以官方 10 家企业为模板，每个模板派生 20 家，编号 E101–E300 / LA101–LA300。
- 保留模板的业务结构：行业、经营范围、财务结构、诉讼/舆情/关联/担保的条数与类型、逾期次数、失信/限高、经营异常、贷款用途/期限/担保方式。
- 金额统一乘以规模系数 k（0.5–2.0），每个字段再加 ±3% 扰动；负债率在模板比率上 ±3%。企业名称、法人、股东自然人、信用代码、证件号、案号、事件编号全部重新生成，地区码与模板一致。
- 勾稽：`owners_equity = total_assets − total_liabilities`，`external_guarantee_amount` = 担保明细之和。
- 只读官方 9 张业务表和 `schema_relationships.csv`，不读 `question_public.csv`、`公开测试集答案.csv`。

## 文件

| 文件 | 用途 |
|------|------|
| `data/` | 9 张业务表 + 表关系，表头与官方一致，可直接导入 |
| `applications.jsonl` | 200 题 runner 输入（`eval.dd04 prepare` 生成，只有 id/question/scenarioId） |
| `facts.csv` | 机械事实标签（负债率、净利率、CAGR、现金流/利润、应收占比、逾期、担保、涉诉、担保圈等），**仅供 eval 离线对照**；不含风险评级和额度答案，`template_enterprise_id` 只用于分组统计 |

## 使用（cwd=ocft-backend）

```bash
# 导入：注意 config.yaml 的 database 段会覆盖 DATABASE_URL，导入前确认目标库
python -m app.dd_import ../测试数据/评测/2026-10-24/dd04-synth-200/data
python -m eval.run --input ../测试数据/评测/2026-10-24/dd04-synth-200/applications.jsonl --output-dir eval/output/dd04-synth-200 --fresh
```

## 验证

`eval.dd04_data` 体检通过（只有 1 条 warning：`loan_application` 有额外列 status，官方包也有这一条）；导入临时 SQLite 后企业 200、申请 200、财务 600、风险 200；名称/法人/案号/事件编号无重复，勾稽 0 差异，数据中不残留模板企业名、法人姓名或 E00x/LA0xx 编号。

## 局限

扰动后档位大体延续模板，但并不保证跟模板的官方评级一致，所以不把模板评级当作答案。规模扩大后也可能触发额度政策中的绝对阈值，这是可以接受的差异。
