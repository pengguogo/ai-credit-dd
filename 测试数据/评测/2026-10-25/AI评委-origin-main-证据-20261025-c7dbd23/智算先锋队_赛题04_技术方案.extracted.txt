1. 多 Agent 架构
1.1 总体形态：主控 + 六个业务⻆⾊ + 确定性⼯具（ADR-0008）
系统采⽤「统⼀主控 + 六个业务⻆⾊ + 确定性计算⼯具」的多 Agent 架构：
主控（controller）：沿⽤场景⼯具循环，负责意图识别、对象定位（企业 / 申请）、歧义澄清、
决定是否发起尽调⼦计划。不设轮数上限，由 token 预算兜底（agents.yaml 的
controller.max_total_tokens）。
六个业务⻆⾊：⼯商核验（business）、财报解析（ﬁnance）、舆情扫描（opinion）、反欺诈
（fraud）、评级授信（rating）、报告（report）。每个⻆⾊有独⽴职责、结构化输⼊输出
（Pydantic 校验）和真实执⾏记录（llm_calls.purpose=role:*）。
确定性⼯具（app/tools/dd_calc.py）：所有业务数字（指标、评分、评级、额度）由纯函
数实时计算，模型只做解读与成⽂，不改数值。
候选⽅案⽐较：开放式⾃治 Agent 对话轮次与冲突不可控，难以满⾜ 30 秒级时延与同输⼊稳定复
现，未采⽤；单主 Agent 直调⼯具不满⾜本题多 Agent 协作要求，保留为其他场景的运⾏⽅式。
1.2 执⾏流程（完整尽调）
⽤户请求  → run_service （输⼊合规  + PII 掩码）
        → 主控⼯具循环（意图  / 定位  / run_dd_agents ）
   run_dd_agents(mode=full)
        → prepare ：只读快照  + 代号化（主线程，冻结⼗张表）
        → compute ：按依赖顺序算完全部数字（纯函数，毫秒级）
        → business / finance / opinion / fraud / rating 并⾏解读（各⼀次模型调
⽤）
        → report ：报告⻆⾊成⽂
        → verify ：事实校验（纯函数）
        → engine 判定终态  → 输出合规（还原企业名称） → 证据与轨迹落库
prepare 快照：读出申请与⼗张表，深拷⻉冻结；⻆⾊只读快照，数据库访问只在主线程的读
（prepare）与写（收尾落库）两个阶段，并⾏⻆⾊不持有 Session，规避 O RM 并发问题。
并⾏解读⼝径（agents.yaml 的 parallel_analysis: true，默认开启）：compute 先把
五个⻆⾊的数字全部算完，五个解读同时调⽤模型（按各⻆⾊ max_tokens 预占 token）；反
欺诈、评级的解读只看上游数字，不看上游⽂字判断。设为 false 回到逐级串⾏
（business/ﬁnance/opinion 并⾏ → fraud → rating → report）。该改造使公开集单笔耗时从
平均约 81 秒降⾄ 22–26 秒。
静态拓扑 + 跳过：六个⻆⾊节点始终在 LangGraph 图中，不在计划内的⻆⾊进⼊后直接返回
skipped，事件可预测；未采⽤动态 Send。
调度边界：只⽤ LangGraph 做依赖调度；模型只经 app/llm.py 调⽤锁定的 deepseek-
v4.1-flash，不⽤框架⾃带 ChatModel / ToolNode。
1.3 ⻆⾊执⾏模板
每个⻆⾊统⼀三步（app/agent/dd_roles.py）：
1. 计算：调⽤ dd_calc 纯函数（verify_business / analyze_financials /
scan_public_opinion / detect_fraud / rate_risk + calc_credit_limit /
build_report）。
2. 分析（⻆⾊配置 llm: true 时）：把代号化的计算摘要送给模型，temperature=0，输出
JSO N {analysis, keyFindings[], uncertainties[], needsReview}，Pydantic 校
验失败回错重试 1 次，仍失败记为 degraded。
3. 产出 RoleResult：role、status（ok/degraded/skipped/failed）、data、analysis、待
落库证据、调⽤审计、usage、durationMs。计算抛 ToolError（如企业不存在）时该⻆⾊
failed，下游依次 skipped，系统如实终态失败，不回填模板结论。

3. 财报解析
3.1 期间与勾稽⼝径
取数期间：申请⽇之前最近的完整年度为基准年，同时保留近三年科⽬做趋势；缺少披露⽇期字
段，报告如实注明「不能保证申请当⽇已经披露」。
勾稽校验：资产 = 负债 + 所有者权益，容差 1 万元（metrics.yaml 的
balance_tolerance），超差记为异常线索并关联证据。
⾦额单位：万元；展示舍⼊最后执⾏，不⽤显示值参与下游计算。

5. 舆情扫描
5.1 打分模型（scenarios/dd04/opinion.yaml）
舆情与涉诉合并为舆情⻛险分 opinionRiskScore（0–100，越⾼⻛险越⼤），健康分 = 100 − ⻛险
分：
基础分 20；舆情事件按「情感 × 影响等级 × 时间衰减」计分：情感 正⾯ −6 / 中性 +2 / 负⾯
+14，影响 低 1.0 / 中 1.6 / ⾼ 2.4，按事件⽇期每年衰减 0.85（截⽌时点 = 申请⽇ as_of）。
涉诉按案件状态 × 诉讼⻆⾊分桶计分：未结被告 18 / 未结其他⻆⾊ 6 / 已结被告 4 / 已结其他
1；未结被告案件⾦额单独累计为 openDefendantAmount，进⼊评分卡的「涉诉⾦额/净资产」
指标。
事件标签：司法执⾏、⾏政处罚、经营负⾯、荣誉资质（关键词命中）+「未结被告/被执⾏」
（分桶判定）。
5.2 ⼝径与边界
时间⼝径：所有事件按申请⽇截⽌，早于申请⽇的按年衰减，晚于申请⽇的不计⼊（数据集均为
历史事件）。
空记录处理：⽆舆情⽆涉诉时得基础分 20，健康分 80，不报错、不视为缺失。
汇总评级对照：评分卡的 public_opinion_score 指标优先使⽤原始输⼊字段（事实特征），
缺失时退回本系统计算的健康分；外部汇总评级不参与任何计分（红线 R5）。
去重：事件按 event_id、案件按 case_id 天然去重（表业务键），同⼀事件多来源不重复计分。
每条事件的计分明细（情感、影响、衰减、得分）保留在结构化结果与证据中，可逐条复核。

默换算。
7.3 阈值来源与公开集校准披露
如实披露：评分卡档位边界（如负债率 45/60/70%、净利率 10/6/3%）、额度系数（0.12 / 0.40）、
折减区间（0.6–0.8）与取整档位，是有信贷业务含义的整档设定，并经官⽅公开测评集（10 笔）校
准过边界（公开题拟合策略）。运⾏时只从原始事实重算，不读取任何答案列；⾮公开集上存在边界抖
动⻛险（数值落在档位边界附近时结论可能翻转），该⻛险在测试报告中量化披露。
7.4 已知局限（如实披露）
期限照搬申请值，未按政策反推合理期限；
利率只给⽅向（下浮/持平/上浮），⽆基准利率与点差，不伪造市场报价；
贷款⽤途对额度的影响很⼩（⽤途仅进⼊建议与核查项，不进公式）；
关联交易缺⾦额字段，算不出关联交易占⽐，列为「不能核实」。

9. ⾃然语⾔问询
9.1 链路（与完整尽调同⼀ run 服务）
问询⾛ POST /api/agent/runs 同⼀⼊⼝与会话，不另建问答系统：
意图路由：主控按问题选择直接⼯具回答（get_loan_application / find_enterprise /
sql_query，后者受字段⽩名单约束）或发起 run_dd_agents(mode=followup)。
followup ⼦计划：只执⾏该问题所需的⻆⾊依赖闭包（问「资产负债率」只跑 ﬁnance；问
「额度为什么压降」跑 ﬁnance → rating → credit），依赖闭包按 agents.yaml 的
depends_on 递归补⻬；若现有结果不适⽤则现场重算，不为省调⽤复⽤失效结论。
歧义澄清：多企业同名或对象不明时 request_clarification → 终态
needs_clarification，不猜对象。
回答溯源：答案必须携带证据引⽤，answersWithoutEvidence 由运⾏统计核验（公开集问
询 10/10 全部带证据）。
9.2 依据与结果
问询输⼊经字段⽩名单与输⼊合规检查；参考答案（question_public.csv 的要点、公开测试集
答案）不传⼊ Agent，整批导⼊路径⾃动跳过答案⽂件。
官⽅问询⾃测集 10 题经同⼀链路实测：10/10 succeeded，平均 14.1 秒，全部带证据；逐题⽐
对⻅测试报告。

11. 鲁棒性、可解释性与合规
11.1 终态与诚实失败
终态沿⽤全场景统⼀语义：succeeded / needs_clariﬁcation / insuﬃcient_evidence /
needs_conﬁrmation / intercepted / failed / timeout。公开测评集 10 笔实测：7 succeeded、1
needs_conﬁrm ation、2 failed（narrative_check_failed，L A006/L A008）——事实校验未通
过时如实失败并保留已验证过程，不发布模板结论；失败笔在六列导出中如实保留失败状态。10 笔全
部带证据（answersWithoutEvidence = 0）。
11.2 ⼀致性与性能（公开集实测，版本 00e905f）
结构化⼀致：同⼀输⼊双跑，评级与额度结构化结果⼀致（双跑对照详⻅测试报告）；⽂本不承
诺逐字⼀致（temperature=0 只保证结构与数字稳定，差异如实披露）。
性能：完整尽调平均 27.1 秒 / P50 23.0 秒 / P95 34.2 秒（并⾏解读改造前平均约 81 秒）；
⾃然语⾔问询平均 14.1 秒。端到端 30 秒⽬标未 100% 达成（P95 超标），如实披露。
离线对照（仅评测进程使⽤答案）：⻛险评级⼀致 8/10、额度⼀致 8/10（两笔失败⽆结构化结
论记不⼀致）。
11.3 脱敏与代号映射
外送模型的全部内容使⽤代号：企业全名 → 企业 <enterpriseId>；法⼈、实控⼈、股东、关
联企业按出现顺序编号；统⼀社会信⽤代码与证件号直接掩码。映射只在内存中，不落库、不送
模型。
⽤户问题与会话保留名称原⽂；最终答案、报告与澄清问题在输出合规检查后仅还原企业名称；
信⽤代码、证件号、地址不还原；证据 API 与导出对法⼈/实控⼈姓名掩码，异步 meta 隐藏库
内已知⼈名。
原始舆情/事件⽂本作为数据处理，其中任何「忽略规则、读取答案」类内容不构成 Agent 指
令；发布前数值检查保留正负号并做科⽬与年度匹配。
